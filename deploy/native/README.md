## 目录和职责

- `/opt/miaoimg/releases/<revision>`：确定版本的服务代码、锁定依赖和编译后的网页资源。`current` 为原子切换的符号链接；运行进程按实际启动版本验收，不能只读链接判断版本。
- `/opt/miaoimg/.oip/runtime-data`：唯一生产账号库、订单、账本、任务、会话和索引；不放进发布包。
- `/opt/miaoimg/media`：用户原件；`images`、`previews`、`db`、`catalog` 为灵感库原图、预览、数据包与展开数据库。
- `/opt/miaoimg/site-current`、`site-assets`、`website-media`、`desktop-downloads`：官网、官网媒体与正式更新包，继续独立发布。
- `/etc/miaoimg/main.env`：实际运行配置，权限 600；密钥文件在 `/opt/miaoimg/secrets`，不进入 Git、日志或发布包。
- `miaoimg.service`：复用现有服务监督入口，管理页面服务 4173、图片/Agent API 4175、档案 API 4176、管理 API 4184，全部设置为回环监听。主服务停止时等待已受理任务收尾。
- Nginx：提供官网和管理 UI 静态文件、媒体 Range 和鉴权后的内部媒体直出，并按原有 API 路由反代。后台静态资源直接由 Nginx 提供，复用管理 API，不再运行重复后台 Node 监督进程。

固定 Node 版本及相应完整依赖构成一次运行交付，不能只替换 `node` 或随意 `npm update`。本次 Node 为 22.23.4；Python 3.10/系统工具兼容性必须用真实启动验证，不能以模块解析检查代替。

Vite 预览仍需要生成短期配置缓存：`web/node_modules/.vite-temp` 指向 `/var/lib/miaoimg/vite-temp`，保持版本代码和依赖只读。不能为解决缓存权限而把整个版本目录开放写入。

大陆机到美国网关的直接 TCP/HTTPS 路径曾超时，因此上游出口单独交给 `miaoimg-egress.service` 管理。它只监听回环端口；私有配置仅将 Yunshu 网关域名走已验证的现有网络出口，国内供应商保持大陆直连。Node 使用实际支持的 `--use-env-proxy`，回环请求由 `NO_PROXY` 排除。地址、认证和节点信息只保存在服务器私有配置，不进入业务源码或桌面安装包；禁止将本轮传文件的临时代理/密钥作为生产运行入口。该出口依赖现有网络服务的可用性，维护时需单独核对，不能把一次健康/模型/额度查询当作永久连通保证。

客户端源码及已安装的 3.1.10 `app.asar` 均核对为：云端 `https://miaoimg.cn`，更新源 `https://miaoimg.cn/desktop-downloads/updates/`；会话和取回地址校验绑定同一 origin。此次保留域名、HTTPS、API 路径及更新包字节，无需仅为服务器换 IP 改客户端地址或发布新包；更换域名/IP origin 则必须另行验收登录恢复、素材地址、任务取回和更新。

原生只读检查入口为 `python3 deploy/native/inspect.py`；候选须显式传入候选 `--unit` 和 `--db`。它只报告本机服务、账号库计数和余额不变量，不读取密钥；不证明外部域名、真实生成、付费结算或跨账号权限已经验收。当前提供 unit、Nginx 片段和检查入口，完整自动发布/回滚工具尚未实现；未实现的门禁不能写成已经自动执行。

在本机使用 `ssh miaoimg-cn python3 /opt/miaoimg-ops/native/inspect.py` 检查实际运行服务。`miaoimg-cn` 使用独立主机 SSH 密钥；美国 `root` 别名继续仅供 Sub2API 运维。旧 Docker 生产脚本已取消隐式美国目标，桌面更新上传默认改为 `miaoimg-cn`。

`miaoimg-backup.timer` 每天上海时间 04:15 后随机十分钟生成唯一最新的压缩账号库快照，与发布共用锁；本次已实际解压并检查恢复库。它不备份媒体，不是异地容灾。新机日志容量上限为持久 100MB、运行时 50MB。当前 TLS 证书有效至 2027-01-08；备案及可执行续期方式后续一起处理，不宣称已经建立自动续期。

现有管理员人工价、积分规则、历史账和上游成本口径均保留。新增大陆服务器的实际采购成本与旧预算可能不同，后续需依据真实费用核对运营成本预算，不能把未核实的新成本直接摊入用户售价。

## 发布和回滚

1. 从明确提交准备新的版本目录和完整资源清单，核实依赖、磁盘、权限、数据路径及上游配置。官网、后台、API、桌面更新按各自职责发布，不因迁移发布新客户端。
2. 候选使用独立账号库、任务/媒体输出和端口；只读共享原件。除应用开关外，用 systemd 网络策略阻止候选访问真实上游。不得让候选消费生产任务、发送邮件、产生订单或扣积分。
3. 检查健康、登录/会话兼容、后台、灵感库、媒体鉴权/Range、已有任务取回及新旧客户端请求。真实生成仅按用户已授权范围执行，健康和菜单验证不能代替出片。
4. 切换共用 `/run/lock/miaoimg-deploy.lock`；暂停会修改相同数据的同步/维护任务，检查未完成任务。SQLite 使用 online backup，先快照再停旧写入方；短暂停写后做最后一次一致性备份和媒体增量同步，不允许中美两份账号库同时接收写入。
5. 切换 `current` 后启动服务并核对实际 PID、启动目录、日志、四个端口与业务。失败恢复旧版本链接和服务；不能用旧数据库覆盖切换后的订单、余额或任务。两机回切须先停新写入方，把最新数据库/新增媒体一致地带回，不能直接启用美国旧库。
6. DNS 切换保留旧值与 TTL；所有 A/AAAA、www 别名、API/支付回调和更新下载均须核对。DNS 缓存期内旧入口只能转到新写入方，不能继续写美国旧库。域名不能接入大陆时保留旧生产，等待条件齐备。

## 备份和清理

账号库每天 online backup 到受限备份目录；定期核对完整性，并验证实际恢复步骤。数据库快照不包含原始媒体，异机媒体备份必须另外安排。迁移未切换前，新机只是某时刻的副本，不能称作最新生产库。

日志使用 systemd journal，设定容量；维护脚本必须适配原生运行方式后才能启用。旧的 Docker 清理/同步 timer 不能原样复制到大陆。版本发布与维护共用锁；正式下载包、用户原片、账本、唯一恢复点和其他任务 WIP 不属于垃圾。

验收完成清理本轮临时下载、解压包、迁移密钥、临时代理、隧道和候选进程；保留必要迁移记录。美国妙图仅在大陆生产和域名链路验收后停止，Sub2API 及所属桥接、数据库、缓存始终保持原运行方式。
