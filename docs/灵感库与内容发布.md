# 灵感库与独立内容发布

## 用户入口

桌面只有一个“灵感库”入口，按实际素材分为“图片 / 视频”。视频包含公开档案的视频记录和人工审核的精选作品；内部来源标识只用于稳定 ID、检索和引用，不作为两个用户分类。模型、题材、主体、人物、视觉风格、场景、构图、镜头、光照、色彩、氛围、用途等是筛选条件。

分类依据媒体文件，不依据提示词中出现的模型名字。例如只有参考图片的 Seedance 提示词仍归图片；同时有图片与视频的记录以视频为主。

详情保留原始提示词、译文、原作来源以及图片/视频参考。原文不被译文覆盖。界面内容按中/英文取已有译文，21 种界面语言走原有词典。

## 内容与客户端分开

| 内容 | 唯一编辑来源 | 发布单元 |
| --- | --- | --- |
| 精选目录、分类、原文、译文和播放配置 | `content/showcase/` | 独立内容目录 |
| 公开档案图片/视频及基础译文 | 既有只读档案服务、数据同步流程 | 档案数据 |
| 经核对的档案译文补充 | `content/archive-translations.json` | 独立内容目录 |
| 灵感库界面、播放器与工具协议 | `desktop/`、`server/` | 客户端或相应服务代码 |

客户端构建不再导入精选目录、播放 JSON 或提示词分片，`renderer/public` 中也不保留这些副本。内容发布不修改桌面安装包、版本号或 `latest*.yml`。

现有旧客户端不能自动获得新的数据协议。首次接入需要一次客户端更新；接入后，素材增删、标题、分类、原文、译文和播放配置更新均不需要重新打客户端包。界面与协议变化仍按客户端发布流程处理。

## 数据协议和缓存

- `/library-content/showcase/current.json` 是轻量目录，含格式、内容版本、题材与作品元数据。
- `/library-content/showcase/releases/<内容哈希>/films/<稳定ID>.json` 存放单条原文、译文与播放配置。
- 同版本 `search.json` 是 Agent/MCP 全文检索数据，只在确实需要检索精选原文时读取，不作为首屏的下载依赖。
- `/library-content/archive/translations.json` 存放补充译文，每条绑定原文 SHA-256。原文不匹配时绝不套用旧译文。

构建产出以内容哈希隔离。先完整上传不可变版本，再原子替换 `current.json`；同一版本的字节不可覆盖。原文和译文、目录和播放信息来自同一版本，打开的旧作品仍可以读取旧版本详情。媒体更新优先使用新地址，保留仍被引用的原资源。

本机 runtime 验证格式、ID、路径、响应类型和大小后才写缓存。异常内容不能覆盖上一份有效缓存；离线重启可以读取已缓存目录与详情。本机只保留当前及最近两个历史版本的缓存。新检索首屏检查当前版本，后续分页复用同一份已验证数据。公开档案网络故障时，结果必须标记 `partial` 并提供重试，不能把部分来源冒充完整结果。

## 界面与 Agent 共用 API

桌面只读接口：

- `GET /api/library/catalog?media=image|video|all`：模型和分组标签。
- `GET /api/library/items?media=...&q=...&tag=...&tool=...&sort=...&offset=...&limit=...`：统一分页检索；最多 24 条。首屏可带 `fresh=1` 检查内容版本。
- `GET /api/library/showcase`：精选目录；`fresh=1` 检查更新，`cached=1` 只读本地缓存。
- `GET /api/library/showcase/films/<ID>?version=<内容哈希>`：指定版本的详情。

内置 Agent 与 MCP 自动注册同一组工具：

- `getInspirationLibraryCatalog`：先查看媒体分类、可用标签值和模型。
- `searchInspirationLibrary`：按媒体、关键词、标签和模型检索，返回原文、已有译文、来源和参考素材。默认每次最多 12 条，保留原有参考图保存功能；不调用生成模型。

界面和工具共用 `createLibraryTools` 及 `ShowcaseContent`，不另外维护 Agent 的静态目录。`source=archive|showcase` 保留为内部兼容参数。返回的稳定 ID 为档案原 ID 或 `showcase:<ID>`。

## 视频封面

视频原片可能通过原作源转发，数据里的 `poster_path` 不代表对应封面已在磁盘上。视频封面请求不能落到官网 HTML。

`miaoimg-library-content.service` 只提供公开内容与封面，监听回环 4177：

1. 优先读取已经交付的本地公开 JPEG，不改写原文件。
2. 缺失时，只为目录中已收录、原作主机符合白名单的视频生成封面。
3. 最多读取原片前 8 MB，禁止上游重定向；ffmpeg 只读本地临时文件，不允许网络协议。
4. 同时最多两个生成任务，相同原作复用同一任务。成功结果写入 `/opt/miaoimg/catalog/video-posters/`；临时片段在成功、失败和退出时删除。
5. 后续读取使用图片缓存。不存在或非法的资源返回 404/502/503，不以 HTML 的 200 响应冒充图片。

Nginx 在主站 server 块独立引入 `deploy/native/library-content.conf`。不要把新的 location 永久塞进其他命名 location 内部。服务必须先在独立端口完成验证，再启用路由；Nginx reload 后等待实际路由就绪，回读内容类型和图片字节。

## 构建与发布命令

所有本轮新增服务、导入、构建与发布代码均为 TypeScript。部署用的 JavaScript 是编译产物，兼容未编入原生 TypeScript 支持的服务器 Node。

```bash
# 在国内工作区运行。输出必须放本轮独立目录，不写入安装包目录。
node scripts/build-showcase-content.ts --output /本轮目录/content/showcase
node scripts/build-library-service.ts --output /本轮目录/service
```

内容构建要求每条精选有原文和中文译文，并核对译文绑定的原文哈希；校验失败时不发布。对外展示的已有中英文内容不在运行时调用模型临时翻译。

将完整内容放到服务器独立候选目录，编译后的服务代码、`package.json` 和发布工具保持相对目录结构。先启动独立回环端口与独立封面缓存，再检查图片原片、视频播放、译文和非法地址。

```bash
# 服务器上先只验证；还会检查每条作品的视频与封面响应类型。
node /候选服务/deploy/native/publish-library-content.js \
  --candidate /候选目录/content/showcase --media-origin https://miaoimg.cn

# 候选通过后激活数据。使用现有生产发布锁，不触碰客户端更新源。
node /候选服务/deploy/native/publish-library-content.js \
  --candidate /候选目录/content/showcase --media-origin https://miaoimg.cn --activate
```

服务代码使用独立的 `/opt/miaoimg/library-content-service/releases/<代码哈希>/`，通过 `current` 指针及 systemd unit 管理。内容在 `/opt/miaoimg/library-content/`。服务代码、内容数据、Nginx 路由是分别验证的步骤，某一步成功不能替代其他步骤。

新素材仍需提供可访问的原片、封面及译文；目录同步和资源检查通过后再更新入口。公开档案上游有缺译文时，按原文哈希补充到独立覆盖表，不能直接改只读数据库造成数据清单计数失配。

## 既有目录服务的发布依赖

当前 4176 档案服务仍使用既有实现；其 `runtime/archive_db.py` 是必需源码模块，不是可以清理的运行缓存。发布归档需包含此模块，且在目标运行用户下实际启动并读取目录。单独检查 Python 文件语法不能证明其导入、只读数据库和临时目录可用。保留现有运行环境中的兼容模块修复，不能在整理时删除其被引用目录。
