# 安全边界与客户端防护

更新时间：2026-10-26

## 结论

妙图桌面包（DMG、安装后的 macOS App、Windows `.exe`）运行在用户控制的电脑上，不能作为可信安全边界。用户可以调试进程、观察请求、修改本地代码并重放请求。因此服务端必须把桌面客户端当作不可信调用方。

这不意味着安装包会暴露供应商 Key。供应商凭据只由服务端密钥目录读取，客户端只提交公开模型标识和用户请求；服务端重新判断账号、模型权限、积分、价格、路由和任务归属。

## 当前防护

- 生成、文本模型和 Agent/MCP 入口在服务端检查登录身份、账号状态、模型权限和积分。
- 上游供应商 Key 不进入桌面包、公开模型目录或普通用户响应。
- 高成本 POST 入口按账号和客户端地址限流，生成任务还限制每个账号的进行中数量。
- 密码重置会撤销该账号的旧会话，再签发新的会话。
- 生产环境的登录 Cookie 与 OAuth 状态 Cookie 使用 `HttpOnly`、`SameSite` 和 `Secure` 属性。

## 可调参数

默认值已经启用；只有需要按部署规模调整时才设置：

```text
MIAO_RATE_IMAGE_PER_MINUTE=12
MIAO_RATE_VIDEO_PER_MINUTE=6
MIAO_RATE_TEXT_PER_MINUTE=80
MIAO_RATE_MEDIA_PER_MINUTE=12
MIAO_RATE_AGENT_PER_MINUTE=40
MIAO_RATE_MCP_PER_MINUTE=80
MIAO_RATE_WEB_PER_MINUTE=80
MIAO_RATE_PROVIDER_PER_MINUTE=20
MIAO_MAX_ACTIVE_GENERATIONS_PER_USER=8
```

这些限制用于降低请求重放和批量滥用的损失，不能证明请求来自官方二进制。
当前限流状态保存在单个 API 进程内存中；如果以后横向扩展多个 API 实例，应把同样的预算下沉到网关或共享存储，并保留服务端账号级的进行中任务上限。

## 发布前检查

1. 在解包的桌面资源中搜索 `ARK_API_KEY`、`YUNSHU_API_KEY`、`SUIHE_API_KEY`、`GROK_API_KEY` 和真实 Key 值，确认没有进入包。
2. 使用普通账号改写请求中的模型、供应商、价格和桌面标记，确认服务端仍按服务端目录、账号权限和账本处理。
3. 清除或重置密码后，确认旧 Cookie 不能继续访问生成、文本、Agent 和工作区接口。
4. 观察限流和进行中任务上限返回 `429`，确认没有产生上游请求和积分流水。
5. 发布后保留服务端审计、账本和上游请求留档；不要把客户端混淆、签名或证书固定当成唯一防线。
