# 安全边界与客户端防护

## 原则

桌面安装包（DMG、安装后的 macOS App、Windows `.exe`）运行在用户控制的电脑上，不是可信边界：用户可以调试进程、观察和重放请求、修改本地代码。服务端必须把桌面客户端当作不可信调用方。

供应商凭据只由服务端从密钥目录读取，不进入桌面包、公开模型目录或普通用户响应。客户端只提交公开模型 ID 和用户请求，服务端重新判断账号、模型权限、积分、价格、渠道和任务归属。

## 现有防护

- 生成、文本模型和 MCP 入口在服务端检查登录身份、账号状态、模型权限和积分。
- 高成本 POST 入口按账号和客户端地址限流，生成任务限制每个账号的进行中数量。
- 重置密码会撤销该账号的旧会话再签发新会话。
- 生产环境的登录 Cookie 带 `HttpOnly`、`SameSite`、`Secure`。

## 限流参数

默认值已启用，只在需要按规模调整时设置：

```text
MIAO_RATE_IMAGE_PER_MINUTE=12
MIAO_RATE_VIDEO_PER_MINUTE=6
MIAO_RATE_TEXT_PER_MINUTE=80
MIAO_RATE_MCP_PER_MINUTE=80
MIAO_RATE_WEB_PER_MINUTE=80
MIAO_MAX_ACTIVE_GENERATIONS_PER_USER=8
```

限流用于降低重放和批量滥用的损失，不能证明请求来自官方客户端。限流状态保存在单个 API 进程内存中；将来横向扩展多个 API 实例时，要把预算下沉到网关或共享存储，并保留服务端账号级的进行中任务上限。

## 发布前检查

1. 在解包的桌面资源中搜索 `ARK_API_KEY`、`YUNSHU_API_KEY`、`SUIHE_API_KEY`、`GROK_API_KEY` 和真实 Key 值，确认没有进包。
2. 用普通账号改写请求里的模型、供应商、价格和桌面标记，确认服务端仍按服务端目录、账号权限和账本处理。
3. 重置密码后，确认旧 Cookie 不能再访问生成、文本、Agent 和工作区接口。
4. 触发限流和进行中任务上限，确认返回 `429`，且没有产生上游请求和积分流水。
5. 保留服务端审计、账本和上游请求留档；不把客户端混淆、签名或证书固定当作唯一防线。
