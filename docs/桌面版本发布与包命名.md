# 桌面版本号、更新记录与包命名

打包、验收和发布步骤见[开发隔离与桌面发布](开发隔离与桌面发布.md)。

## 版本号

三段式 `主版本.次版本.修订版本`，来自 `desktop/package.json`：

- 每次正式发布只把最后一位加一：3.2.0 → 3.2.1 → 3.2.2 …
- 最后一位到 9 之后进位到中间一位并归零：3.2.9 → 3.3.0；中间一位同理：3.9.9 → 4.0.0。
- 撤销的未发布候选号不复用。
- 一批用户可见修改进入正式包后，再有用户可见修改就递增版本，并重新打包；不能把两批验收塞进同一版本号，也不能只给旧包改名。

## 更新记录

- 写在 `server/release-notes.ts`，桌面「版本更新记录」和官网更新日志共用。标题写 `zh`/`en` 字段，条目写 `item('中文', 'English')`。
- 每版固定三栏，顺序不变，没内容的栏留空数组：
  - **新增功能**（`features`）：原来没有、现在能做的事；
  - **优化改进**（`improvements`）：原有功能更好用；
  - **Bug 修复**（`fixes`）：原来不对、现在修好。
- 一句话写清哪个界面、做什么或哪里不对、现在怎样。不写实现、部署、供应商、渠道、服务器等内部信息，不设「已知问题」，不写撤销的候选版本。
- 发布前运行 `node desktop/scripts/verify-release-notes.ts`：检查当前版本有记录、每版三栏齐全、没有禁用词（历史记录也一起检查）。

## 安装包命名

正式安装包文件名必须带版本号（以 3.2.1 为例）：

- `妙图-3.2.1-arm64.dmg`、`妙图-3.2.1-x64.dmg`
- `妙图-3.2.1-arm64.zip`、`妙图-3.2.1-x64.zip`
- `妙图-3.2.1-Windows-x64.exe`

更新源同时提供下载页用的版本化别名：

- `miaoimg-desktop-mac-arm64-3.2.1.dmg`
- `miaoimg-desktop-mac-x64-3.2.1.dmg`
- `miaoimg-desktop-windows-3.2.1.exe`

固定兼容入口 `miaoimg-desktop-mac-arm64.dmg`、`miaoimg-desktop-mac-x64.dmg`、`miaoimg-desktop-windows.exe` 每次发布跟随当前版本更新，不作为归档名称。Mac 安装脚本优先用版本化文件名。

## 从云端打包到更新源

1. 构建输出与正式下载使用产品名：国内 `妙图-<版本>-*`，海外 `MiaoImg-<版本>-*`。GitHub 会移除附件名里的中文，临时 Release 因此使用仓库英文名传输：国内 `MiaoTu-<版本>-*`，海外 `MiaoImg-<版本>-*`。国内正式交付前恢复为“妙图-”，不把国内产品叫作 MiaoImg。
2. 每个阶段的更新元数据 `url`、`path` 必须与该阶段文件名一致。取回国内临时包时，将 `MiaoTu-` 与元数据引用一起恢复为“妙图-”；只改名不改变包字节或 SHA-512。
3. 用 `deploy/verify-update-metadata.py` 在本地核对，再执行 `deploy/publish-desktop-updates.sh`；本机可通过 `MIAO_DESKTOP_RELEASE_DIR` 指定仓库外的本轮产物目录。
4. 客户端从对应产品线的正式更新源取包；GitHub 正式 Release 的 Latest、版本和安装附件必须同步当前正式版。当前附件完整验证后，清理旧安装附件及其 blockmap；保留历史说明和源码标签。不能把另一个产品线的仓库或更新源混用。

## 同版本重打包

用户明确要求保持产品版本号重新打包时，递增 `desktop/package.json` 的 `desktopBuild`，并用 `MIAO_DESKTOP_BUILD_ID=b<desktopBuild>` 区分新附件。元数据仍写产品版本号和新的 `build`，附件字节按构建编号保持不可变；正式兼容下载入口切到新构建，旧构建在新包完整验证后再清理。已安装且不支持构建编号的旧客户端需重新下载安装一次，新客户端可检查同产品版本的新构建。Windows 同版本构建提供官方安装程序重新下载，正常跨版本自动更新路径保留。

## 仓库临时公开

仓库平时是私有的。私有 Actions 受账单/配额阻断时，用户已授权临时公开仓库完成 Mac/Windows 打包：

- 公开前核对仓库身份和跟踪内容（不含参考源码、内部资料）。
- 打包完成或失败退出，都立即把仓库改回私有。
- 取回并核对产物后，删除临时构建/验收 Release 和 tag；不把临时 Release 标成正式 Latest。
