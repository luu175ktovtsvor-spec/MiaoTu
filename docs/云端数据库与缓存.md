# 云端数据库与缓存

2026-10-29：美国正式服务器已从账号 SQLite 切换到妙图独立 PostgreSQL 18.6 与 Redis 8.0.5。旧账号 SQLite 冻结保留，正式每日备份使用 `management-native-latest.pgdump`。本次只发布服务器迁移代码，没有发布桌面安装包；部署提交、数据核对与恢复验证记录在仓库外 `本地资料/开发记录/正式PostgreSQL迁移-20261029/`。

## 数据归属

| 组件 | 职责 | 持久化与恢复 |
| --- | --- | --- |
| PostgreSQL | 服务器账号、会话、订单、积分账本、任务、反馈与短期媒体索引 | 唯一业务真值；用 `pg_dump` 备份、在空库验证恢复 |
| Redis | API 与登录限流、短期缓存 | 可丢弃；不存余额、订单、支付结果、任务终态或会话权限 |
| 桌面 SQLite | 用户电脑上的项目、画布、会话与本机文件索引 | 保持 `desktop.sqlite`，不上传整库、不迁到 PostgreSQL |
| 公共目录 SQLite | Python 灵感库与案例目录 | 独立只读目录，不属于账号库迁移 |

妙图使用自己的原生 PostgreSQL、Redis 与凭据，不连接模型网关现有的数据库或 Redis。

同一物理服务器可以承载国内、海外两套业务。每套业务使用独立的服务进程、配置、数据库、数据库角色、Redis 命名空间和更新源；本地安装包的应用身份与 profile 也必须独立。`MIAO_EDITION` 只标识服务实例，不会自动实现海外登录、支付或客户端分包。

## 配置与启动

配置模板是 [cloud-data.env.example](../deploy/native/cloud-data.env.example)，实际值只放服务器私有配置。密码中的特殊字符必须进行 URL 编码，连接串不能进入日志、Git 或安装包。

- `MIAO_DATABASE_URL`：妙图专属 PostgreSQL 数据库，默认使用 `public` schema。生产模式缺少配置时拒绝退回 SQLite。
- `MIAO_DB_POOL_MAX`：每个 Node 进程的连接池上限，默认 10；API 与管理进程分别计数，两套业务要一起核算总连接数。
- `MIAO_REDIS_URL`：妙图专属 Redis 凭据，只监听回环。
- `MIAO_REDIS_NAMESPACE`：国内可用 `miaoimg:cn`，海外使用不同值，例如 `miaoimg:global`。
- `MIAO_REQUIRE_IMPORTED_DATABASE=true`：既有账号库迁移后必须保留此校验，防止误连空库。全新海外库没有 SQLite 历史导入时才设为 `false`。

`scripts/check-data-services.ts` 在 systemd 启动前校验 PostgreSQL、导入标记和 Redis。数据库结构初始化串行执行；普通业务事务各自占用连接，不把所有请求放在单个连接上排队。

建议从 PostgreSQL 18、Redis 8 开始。数据库角色只拥有自己的数据库，不授予超级用户、创建数据库、创建角色权限。数据库使用 `TEMPLATE template0 ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C'` 创建，保留路径前缀范围查询的逐字节排序语义；启动会检查排序规则。连接只开放回环，Redis 的业务角色不应拥有 `CONFIG`、`ACL`、`FLUSHALL`、`FLUSHDB` 或 `SHUTDOWN` 权限。

Redis 使用 `maxmemory-policy noeviction`，避免提前淘汰限流计数。缓存有短 TTL 和单条大小上限，首批用于资料库统计。Redis 故障时，普通缓存回源；受保护请求的限流返回 503，不能悄悄退回各进程独立计数。账号的进行中任务上限仍在 PostgreSQL 事务里检查，默认 8，由 `MIAO_MAX_ACTIVE_GENERATIONS_PER_USER` 配置。

限流角色需要 `PING`、`AUTH`、`HELLO`、`SELECT`、`CLIENT SETNAME/SETINFO`、`GET`、`SET`、`DEL`、`INCR`、`PTTL`、`PEXPIRE` 和 `EVAL`。国内角色只允许键模式 `~{miaoimg:cn:limit}:*` 与 `~miaoimg:cn:cache:*`；海外替换为自己的命名空间。不要把默认管理员凭据交给应用。

## 从 SQLite 导入

只读演练和正式导入都以 SQLite **在线 backup 生成的独立快照**为源，不删除原库。目标必须是单独的空数据库。数据库角色与正式服务使用同一个拥有者，避免函数和表的所有权不一致。

```bash
# MIAO_DATABASE_URL 从私有环境载入，勿写在命令行或终端历史里。
node scripts/migrate-management-postgres.ts \
  --source /private/management-snapshot.sqlite \
  --report /private/migration-dry-run.json

# dry-run 校验完成后回滚目标；--apply 才提交到空库。
node scripts/migrate-management-postgres.ts \
  --source /private/management-snapshot.sqlite \
  --report /private/migration-applied.json --apply
```

脚本校验源库完整性、外键、每张表行数和逐行摘要。历史声明为 INTEGER 的积分列可能实际包含小数，导入会转为 NUMERIC，并在报告中记录。整数分的支付金额保留整数单位。会话、密码哈希、旧任务参数及价格快照按原值导入。

导入是单个事务；提交前失败回滚，不能覆盖非空目标。提交回执不明或提交后报告写入失败时，应保留目标并检查导入标记，禁止清空后盲目重试。每次演练使用独立报告文件。只读演练期间源库继续收到的订单不会自动出现在目标，所以演练结果不能直接用于正式切换。

## 正式切换与回退

1. 先在独立数据库、媒体目录、Redis 命名空间和端口验收；保留经过验证的明确源码版本。
2. 在维护窗口内持有发布锁，暂停新增提交与会写账号库的维护程序，等待已受理任务完成；停止旧写入进程。
3. 再制作最终 SQLite 一致性快照，记录账本、订单、余额、任务及会话计数；将最终快照导入全新 PostgreSQL 库并验证。
4. 同时更新私有数据库配置、启动预检、备份服务和代码版本。确认始终只有一套业务写入方，再恢复请求。 原生运维目录 `/opt/miaoimg-ops/native/` 必须同步同版 `backup.py`、`inspect-native.py`、`postgres_runtime.py`；安装新的应用和备份 service 后执行 `systemctl daemon-reload`，不能只换业务源码。
5. 核对登录、原有会话、余额与账本、订单回调幂等、原任务取回、旧客户端兼容以及 Redis 限流。真实生成单独取得授权，不用重复 POST 验证已受理任务。
6. 原 SQLite 及原快照冻结保留；开始写入 PostgreSQL 后，禁止将服务切回旧 SQLite 或用旧整库覆盖新交易。代码回退必须仍兼容 PostgreSQL；否则保持维护状态修复或执行另行核实的数据迁移。

### 隔离候选

原生 API 候选设置 `MIAO_CANDIDATE_MODE=true`，显式指定独立的 `OIP_DATA_DIR`、`OIP_MEDIA_ROOT`、名称含 `candidate` 的数据库和 Redis 命名空间。服务会禁用队列消费、自动取回、供应商对账、真实生成、支付和邮件入口，并禁止外部 fetch。候选不加载正式更新源，不使用正式可写媒体目录。

这项开关针对服务器入口，不能替代独立数据库、路径隔离和对手工运维脚本的检查。普通用户交互验收仍使用获准的现有账号，不创建测试账号或修改正式余额。

## 备份与巡检

- `deploy/native/backup.py` 按私有配置选择活跃数据库。PostgreSQL 使用 custom-format `pg_dump`，完整读取归档校验后才原子替换 `management-native-latest.pgdump`；失败保留上一份备份。
- 原来的 `management-native-latest.sqlite.gz` 是迁移前恢复点，不能用它覆盖 PostgreSQL 的新交易。
- 定期将 `.pgdump` 恢复到另一个空库，核对表计数、数据摘要及余额不变量；文件存在或归档目录可读取不等于已验证恢复。
- `inspect-native.py` 从私有环境读取连接配置，PostgreSQL 查询强制只读，报告聚合计数、任务状态与余额差异，并检查 Redis；连接串不出现在报告里。
- 备份只含数据库，不含媒体；同机备份也不等于异地容灾。

历史 SQLite 布局工具 `migrate-projects.ts`、`migrate-media-blobs.ts` 和网页工作区退役脚本在配置 PostgreSQL 时拒绝执行，避免使用旧 SQLite 索引回收新媒体。日常桌面临时媒体继续由现有带引用复查的协议维护入口处理。

## 开发约定

服务器通过 `await ManagementStore.open()` 初始化；所有数据库调用和事务回调都要等待完成。同一事务绑定同一个 PostgreSQL client，不能在事务中混用池外查询。积分、任务、订单与文字结算使用行锁或业务锁，保留唯一约束与幂等标识。

共用素材代码也使用异步接口，但 `LocalStore.open()` 始终显式打开本机 SQLite，不继承云端数据库地址。媒体先落盘、后提交引用；旧字节只在外层事务提交后回收，且在同一账号媒体锁内再次查引用。异步权限能力与待清理字节必须按请求隔离，不能用进程级临时变量共享。

SQLite 兼容的 JSON、占位符与少量表达式集中在 `cloud-database.ts`；新增 SQL 必须同时检查数据库类型、空值语义和参数绑定。数据库迁移本身不能证明 500 人在线或数千个上游任务的容量，仍需在实际服务器上按真实任务分布单独压测。
