# 开发隔离与桌面发布

适用日期：2026-10-26。本文依据当前源码入口整理，是后续执行规则；提到的缺口不代表已经完成自动化。执行前读取根目录 `AGENTS.md`，版本和运行状态以本次核查为准。

## 当前架构与修改范围

唯一维护仓库是 `/Users/cch/Developer/miaoimg/main`。桌面在本机直接用 Node + Electron 开发，不要求安装或启动 Docker。生产服务镜像默认在远端服务器构建；服务器候选实例通过 SSH 隧道访问。仓库里的 Compose 和本地构建镜像选项是服务端备选，不是桌面启动方式。

| 修改位置 | 运行职责 | 需要验证和交付的范围 |
|---|---|---|
| `desktop/renderer/` | 桌面界面、节点与操作 | 本机完整 Electron → Mac 真包 → Windows 真包 → 更新；无需仅为此重发云端 |
| `desktop/` 宿主、runtime、cloud、本机工具 | 本机项目、账号分区、任务取回和云端请求 | 桌面流程；云端协议变化时再加远端候选与旧版兼容验证 |
| `server/`、共用协议/资源 | 云端 API；部分模块也编入桌面 `.app` | 先沿调用与导入确认两端影响；目录叫 server 不代表只发服务器 |
| `web/src/landing/` | 官网静态页面 | 官网预览、现有媒体播放、静态发布及下载入口；通常无需桌面打包 |
| `web/src/admin/`、管理 API | 模型开关、渠道、价格与账户管理 | 数据副本验收、独立管理容器发布；共用 API 有变化时一并验证 |
| `deploy/`、systemd、网关 | 运维与独立服务 | 按实际组件安装和验证；不因文档或 unit 修订重打桌面包 |

桌面启动的是本机 runtime 和画布，项目、媒体、会话保存在本机 workspace。云端提供登录、模型目录、报价、提交、账单与任务结果等能力。豆包/Dola 的浏览器登录和平台任务是本机 Session 路径，需要独立分区与真实页面验证，不能用云端容器健康替代。官网的 Vite 页面也不能替代桌面宿主。

## 本机源码开发

首次安装或 lockfile 发生变化时，在仓库根执行 `npm run setup`；它安装根、desktop 和 renderer 三处依赖，不拉取整套公开素材。Node 最低 22.19，当前云端打包使用 Node 24。已有依赖不必每次重装。

先核对 Git 改动、正在运行的正式 App、本轮进程和端口，不覆盖其他工作的修改。每次验收建立独立目录，例如：

```bash
cd /Users/cch/Developer/miaoimg/main
task_root=$(mktemp -d /Users/cch/Developer/miaoimg/本地资料/开发记录/desktop-dev-XXXXXXXX)
MIAO_DESKTOP_USER_DATA_DIR="$task_root/profile" \
MIAO_DESKTOP_DATA_DIR="$task_root/workspace" \
MIAO_DESKTOP_DISABLE_UPDATES=1 \
MIAO_DESKTOP_NO_GENERATION=1 \
MIAO_ALLOW_INSECURE_CLOUD_ORIGIN=1 \
MIAO_CLOUD_ORIGIN=http://127.0.0.1:9 \
npm run dev
```

这个示例故意使用不可达云端地址，只用于启动与不依赖云端的界面/本机行为检查，登录、目录和在线任务失败属于预期，不能当完整验收。需要在线能力时，先启动远端候选并验证隧道，再把 `MIAO_CLOUD_ORIGIN` 换成其实际可访问的回环入口。不能直接照抄不存在的候选端口。正式 API 只用于已获授权的专用验收账号与范围；登录、退出和会话刷新也会写服务端状态，不应描述为“完全只读”。

`npm run dev` / `npm run preview` 都会先重新准备 `.app`，然后启动 Electron；`npm run build` 只准备 `.app`，不启动也不产生安装包。准备过程会重建 `desktop/.app`，所以同一源码目录不要同时构建多个候选、运行依赖同一产物的开发进程，或把另一项工作的 `.app` 清掉。先退出自己的开发实例再重建。

`npm run desktop:renderer` 仅适合界面静态调试，没有完整本机 API。登录、保存、任务、媒体、IPC 和本机工具必须回到完整 Electron 验证。官网/API 的 `npm run dev:web` 会经 `web/scripts/with_api.ts` 启动服务，不是纯静态预览，单独核对数据库路径、凭据及副作用后才运行。

## 实际生效的隔离配置

| 配置 | 当前作用与限制 |
|---|---|
| `MIAO_DESKTOP_USER_DATA_DIR` | 源码版指定 Electron profile；打包版不读取它来改 profile |
| `--user-data-dir=<绝对路径>` | 打包版使用的 profile 隔离参数；与独立 workspace 同时指定 |
| `MIAO_DESKTOP_DATA_DIR` | 本机工作区，包括项目、会话、平台账号数据、工具与预览；不能指向用户正式 workspace |
| `MIAO_CLOUD_ORIGIN` | 桌面云端网关地址，源码与真包均会读取；不设置就连接正式官网 API，独立 profile 本身不会隔离云端 |
| `MIAO_ALLOW_INSECURE_CLOUD_ORIGIN=1` | 仅显式允许回环 HTTP 测试地址；使用本机隧道或本文断网地址时须同时设置，否则网关在启动时拒绝 HTTP；正式构建与用户启动不设此变量 |
| `MIAO_DESKTOP_NO_GENERATION=1` | 当前 runtime、cloud 和本机平台宿主有相应生成拦截；不是对邮件、支付、账号修改、任意外部工具的全局断网开关 |
| `MIAO_DESKTOP_DISABLE_UPDATES=1` | 普通开发和候选验收禁用应用更新；专门验收更新时仅对隔离旧版解除 |
| `MIAO_DESKTOP_UPDATE_FEED` | macOS 自有更新路径可用的候选源；Windows 的 electron-updater 读取安装副本内 `resources/app-update.yml`，仅改此环境变量不够 |
| `MIAO_DESKTOP_DISABLE_SYNC` | 验收脚本传入但当前业务代码没有读取；不能作为已实现的同步隔离开关 |
| `ENABLE_MODEL_CALLS=false` | 服务端模型调用限制；不等于禁用所有后台任务或所有第三方副作用 |

不要从正式 profile 复制 Cookie、平台账户分区或凭据来省略登录。需要存量项目复现时，按授权最小范围准备独立副本；活动 SQLite 用在线 backup，不复制正在变化的数据库/WAL。禁止候选客户端读写正式用户项目。调试端口仅绑回环，使用前确认没有别人的调试实例。

## 远端 API、管理端和模型联调

纯桌面修改不必新建服务器环境。涉及服务端的改动，从明确提交构建远端独立候选镜像；核实已有候选，避免重复常驻。可以使用 `deploy/acceptance-container.sh --image <候选镜像> --name miaoimg-acc-<本轮标识>`，但启动前必须核对脚本、挂载和副作用。

现有脚本使用生产 SQLite 在线副本、只读媒体、服务器回环端口和禁用模型调用，适用于菜单、权限、报价和管理页面等受限验证。它的媒体是只读的，不是可上传、可生成的完整测试环境；需要写入时另设候选输出目录，不要把只读挂载改成生产可写。复制的数据库也可能含历史任务；队列、邮件、支付及定时任务须按实际入口检查，不能仅靠一个生成开关保证安全。

通过脚本输出的 SSH 隧道，用自己的 Chrome 验收网页；桌面在线联调还须将本轮 Electron 的 `MIAO_CLOUD_ORIGIN` 指向已验证候选入口。修改模型能力时覆盖节点菜单、切模型旧参数清理、Agent、服务端预扣前校验、上游适配、报价/结算和管理端。不支持的组合不可展示或提交。上游未受理、已受理、失败、结果不明必须区分；结果不明不能重新 POST 试单。

## 桌面打包与真包验收

1. 先完成源码 Electron 的受影响链路验收，再冻结明确提交。版本从 `desktop/package.json` 读取，修改用户可见行为另增版本并同步发布说明、必要 lockfile；根、web 和 renderer 的版本各有职责，不要求机械改成同一数字。
2. 常用入口是 `.github/workflows/desktop-macos-package.yml`、`desktop-windows-package.yml`；也可在具备对应平台环境的机器执行 `npm --prefix desktop run package:mac` 或 `package:windows`。这些命令产物在 `desktop/release/`，`--publish never` 不会发布正式更新源。新推送命中 workflow paths 会自动触发打包，打包任务还可能保存临时 Release；不能把“push”视为没有外部动作。
3. 当前 Mac 任务构建 arm64/x64，但仅启动 runner 匹配架构的应用；另一架构构建成功不等于其运行验收。Windows 任务安装到 runner 临时目录并启动。现有 `accept-login.ts` 覆盖其实际检查的登录/重启等流程，并禁止真实生成；不能据此声称全部节点出片、所有架构和旧数据迁移均通过。
4. Mac 在用户本机验收时，从候选 DMG/ZIP 取出 `.app` 到本轮独立目录，直接启动其中的可执行文件。不要拖入 `/Applications`，不要退出或替换用户正在用的妙图。启动示例见下方；新 profile 不能证明存量 workspace 迁移，涉及迁移时另用获授权的独立数据副本验证，并先备份副本。
5. 使用已有授权的验收账号，凭据只从受保护环境注入；不写日志、命令正文、仓库或包。未授权真实生成时保持拦截，不为了“完整”发付费请求；记录未验收的生成组合。验证范围随修改而定，包括启动、登录/退出、项目保存与恢复、任务归属、切模型、菜单和报价、本机账号、媒体读取及关闭/重启。

Mac 真包启动模板（把第一行改为实际解包位置，`task_root` 沿用本轮隔离目录）：

```bash
candidate_app="$task_root/candidate/妙图.app"
MIAO_DESKTOP_DATA_DIR="$task_root/package-workspace" \
MIAO_DESKTOP_DISABLE_UPDATES=1 \
MIAO_DESKTOP_NO_GENERATION=1 \
MIAO_ALLOW_INSECURE_CLOUD_ORIGIN=1 \
MIAO_CLOUD_ORIGIN=http://127.0.0.1:9 \
"$candidate_app/Contents/MacOS/妙图" --user-data-dir="$task_root/package-profile"
```

模板仍默认断开云端；联调时按前述规则替换云端地址。当前 Mac 包使用 ad-hoc 签名且未公证，Windows 也没有代码签名；不能将其描述为已具备 Apple 公证或 Windows 信誉背书。签名、首次打开提示及不同系统的安装行为需分别记录。

## 更新验收与正式切换

打包、上传临时 Release、发布官网、发布 API、发布管理端、切换客户端更新源是不同操作。某个操作成功不能代替其他组件已更新。

正式发布前先准备候选更新目录，安装包完整上传并核验版本、大小、SHA-512，然后使用独立旧版实例检查发现及下载。Mac 设置候选 feed；Windows 只修改隔离安装副本的 `resources/app-update.yml`，参考 `desktop-update-acceptance.yml`。`accept-update.ts` 检查到 `ready`，并不点击安装；不能说它已验证完整安装替换与重启。确需验证完整升级时，只操作一次性安装副本、独立 workspace 和 profile，安装前确认目标路径，绝不使用用户当前 App。

共享 API 或数据库有变更时，先验证对仍在线旧客户端兼容，再通过正式入口部署 API/管理端，最后开放依赖新接口的客户端。不能新包已发、服务还不支持；也不能新服务上线立刻破坏旧包。数据库采用兼容增量迁移，回滚应用保留新账单和订单，不能恢复旧整库来回滚代码。

完成验收后才执行 `deploy/publish-desktop-updates.sh <版本>` 的正式入口；其发布负责人变量是发布意图确认，不是业务验收证明。它会 staging 上传、核验，再逐项替换元数据，并非所有文件和两个平台一次全局原子切换。已有脚本使用覆盖式移动，因此“禁止覆盖已发版本字节”仍需发布者检查；同版本文件不同哈希就停止，另增版本。不能把规则说成已经有强制不可变门禁。

目前没有已核实的桌面分群更新/完整灰度平台，正式 `latest*.yml` 会影响读取它的普通用户。候选未通过时不改正式元数据；发布后客户端版本不得倒退，必要时发布更高修复版本。服务容器可恢复保留的回滚点，但单机切换不承诺零停机。

私有 Actions 受账单/配额阻断时，用户已授权本项目临时公开打包、取回后恢复私有。这是异常处理，不是常规开发步骤；切换前核对仓库身份与跟踪内容，完成或失败退出均恢复私有，取回并核对产物后删除临时构建/验收 Release 和 tag。不得把临时 Release 标成正式 Latest。

## 验收记录与收尾

仓库文档记录可持续执行的架构、规则、命令及已知限制；每次生产状态和验收事实放在仓库外 `本地资料/开发记录/`。记录至少包含：修改范围、Git 提交/未提交状态、候选/正式版本、实际验收的平台架构与链路、未验证项、部署组件、恢复方式、空间前后值及清理结果。不要以日历日期或历史表代替实际运行 revision。

结束时只停止本轮记录的 Electron、隧道、静态服务和候选容器，保留用户 App、他人任务、现有生产链路。先停止依赖产物的本轮进程，再核对归属删除临时 profile、输出、构建目录和无引用候选包；正式下载确认完整后再清本地副本。服务器候选清理必须写具体实例名，不使用无参数 `--down` 扫掉所有候选。

磁盘清理按 `AGENTS.md` 与 `deploy/README.md` 执行。正式原片、播放分段、灵感库、索引、账本和运行镜像均不是开发垃圾。规则不能替代容量规划：持续增加的有效媒体或安装包仍会占满磁盘，接近构建空间下限时应暂停新构建，评估扩盘或有索引的存储迁移，不能靠删除用户素材维持发布。
