# macOS 安装、官网与历史版本发布规范

本规范同时约束 Mac 安装包、官网下载安装说明、更新日志、安装脚本和更新源。发布者必须逐项核对，不能以本机源码运行成功代替普通用户首次安装成功。

## 签名、公证和首次打开

- ad-hoc / 自签名只能用于应用完整性检查，不是 Apple Developer ID。`codesign --verify` 通过，不代表 Gatekeeper 接受或 Apple 公证通过。
- 公开分发的正式可信链路需要 Apple Developer Program 会员、带私钥的 Developer ID Application 证书、Apple 公证成功及相应 stapler 票据。凭据只进入钥匙串或受保护 CI secret，不放在源码、日志、脚本参数记录和安装包中。
- 没有上述资格时，必须明确说明“当前未经过 Developer ID 签名与 Apple 公证”，提供系统设置中针对妙图的“仍要打开”步骤，以及可审阅的官方安装脚本；不能宣传为双击无提示、已获得 Apple 安全背书。
- 禁止让用户全局关闭 Gatekeeper、修改系统安全策略或递归清理整个 Applications 的属性。辅助脚本只处理已校验的妙图应用副本。
- “Apple 无法验证”与“已损坏 / 包含恶意软件 / 签名完整性失败”分开处理。后者先检查文件与签名，不能当普通首次使用提示强制放行。

## Mac 验收必须记录两条独立链路

1. 功能验收：明确提交的安装包，使用独立 profile/workspace，验证实际启动及受影响功能；保留用户现有应用、项目和登录状态。
2. 分发验收：从官网通过浏览器下载当前正式 DMG，记录系统版本、下载隔离属性、镜像内实际版本/架构和签名状态，验证 Finder 首次安装/打开行为。curl 下载、解压后直接运行二进制、手动清理隔离属性后的启动，不能替代此验收。

正式签名版另外要求 `codesign --verify --deep --strict`、Developer ID 证书链/Team ID、`spctl --assess --type execute`、公证 Accepted、`stapler validate`；在无历史白名单/干净 Mac 上验证浏览器下载后首次打开，并记录是否仍有正常的首次下载确认。两个 Mac 架构分别记录实际运行范围；构建成功不等于另一架构真机验证。

## 官网、版本记录和安装脚本

- 正式版本以服务器 `latest.yml` 和 `latest-mac.yml` 为事实，两者必须一致。源码 package.json、候选包和发布说明条目都不能单独证明已发布。
- 官网从两个正式更新源读取版本；版本化下载入口和“最新”标签跟随实际发布版本。更新日志复用 `server/release-notes.ts`，只列出不高于正式版本的历史记录。读取失败明确提示，不将候选版或过期页面标成最新。
- 发布说明只写真实的用户可见修复与体验改进，不写内部部署记录、无验证的能力或撤销的候选版本。
- `deploy/install-mac.sh` 不写死版本。运行时读取正式 Mac 元数据，选择真实芯片（包括 Rosetta 场景），验证文件大小/SHA-512、应用标识、镜像内版本、芯片架构和签名完整性；验证失败不得覆盖原应用。
- 不自动降级，不覆盖正在运行的目标应用，不修改用户数据。复制与验证成功前保留原应用，替换失败应恢复；临时下载、挂载和 staging 在退出时回收。
- `--verify-only` 只下载检查，不安装；`--destination <绝对路径> --no-launch` 用于隔离安装验收，禁止验收覆盖用户当前应用。
- 每次发布更新包时同步上传最新的安装脚本。官网是独立静态发布单元，更新包发布后必须更新/回读官网版本、更新日志、说明和脚本，不能只改更新源。

## 是否重新打包

- 仅官网、外置安装脚本或运维文档变化，可以独立发布，不因这些变化重打桌面包。
- 修改应用内容、DMG 内辅助程序、签名、公证或重新封装 DMG/ZIP，会改变包字节，必须发布递增版本，重新计算全部元数据；不得同名覆盖已发安装包或只给旧包改名。
- 正式签名需要从明确提交重新构建与验收。没有会员/证书时不反复重打未公证包并声称解决系统信任问题。

## 历史版本与收尾

- 更新日志保留真实历史，已撤销候选不混入正式记录；旧版保留必要服务兼容，不因清文件破坏取回/账号数据。
- 服务器优先保留当前正式版及上一份实际完整、可恢复的正式包，版本化文件和固定兼容别名分清；没有核实文件完整性前不按版本数字推断“上一版”。历史正式归档可保留在受保护的发布存储中。
- 清理前核对 latest 元数据、版本化/固定下载链接、安装脚本、断点续传和历史归档引用。没有明确删除授权，不批量删除正式历史 Release、旧版用户数据或用户当前应用。
- 临时构建/验收 Release 与 tag、废弃候选、下载包和解压目录在取回必要脱敏证据后清理。恢复仓库私有状态，停止本轮进程和隧道，卸载自己的镜像。
