# 模型成本与积分（内部）

只给服务端和管理端使用。公开接口、画布和节点只出现积分，不出现供应商、人民币/美元单价或渠道倍率。各模型能力与渠道见[模型参数对照](模型参数对照.md)。

## 基本口径

- 1 积分 = 1 元。赠送积分不是收入。
- 询价、预扣、结算共用服务端同一计价函数，下单与询价共用服务端素材探测（时长、张数由服务端读原文件）。
- 视频创建前按模型、分辨率、模式、声音和输入媒体预扣；成功后按实际用量结算并退还差额；失败、被拒或取消且未提交的退回。预扣是给用户的最高扣费承诺，实际成本超过预扣时只在管理端记录应收与差额，不追加扣款、不扣成负余额。
- 已开始提交或结果不明的任务，不因缺少任务 ID 就推断未收费；提交边界与取消检查在同一数据库事务内协调，取消后不再发请求。
- 每个任务冻结提交时的价格策略、人工价、采购参数和渠道快照；之后改价、改渠道不重算旧任务，也不回写历史账单。
- 管理员按模型/档位填写的人工价优先，且是最终客户价，不再叠加默认加价。

## 视频售价

**默认自动价 = 本次采购成本 + 输出秒数 × 加价**。加价默认 0.10 元/输出秒，管理端可调，不低于 0.10。支付手续费和服务器费用不放大客户报价（只作内部记录）；这个差价是加价，不是承诺净利。总额保留四位小数，目录里的秒价只是参考展示，H3 的 Context IR、参考素材和长视频档按单计算。

**人工秒价**：用于输出秒数；参考视频、超额图片、Context IR 等按采购成本另行传递，不再加价。在途报价与预扣时的人工价不一致时，扣款前拒绝并要求重新询价。

### 穗禾 Seedance

- 采购成本 = 火山官方 token 价 × 采购折扣，折扣只乘一次：2.5、2.0 为 0.81；2.0 Fast、Mini 为 0.60。

  | 模型 | 官方 token 价（元/百万，无输入视频 / 含输入视频） |
  | --- | --- |
  | 2.5 | 480p/720p 70/42；1080p 77/46 |
  | 2.0 | 480p/720p 46/28；1080p 51/31；4K 26/16 |
  | 2.0 Fast | 480p/720p 37/22 |
  | 2.0 Mini | 480p/720p 23/14 |

- 询价调用穗禾 `/v1/billing/video-pre-estimate`（不创建任务，1000 上游 credits = 1 元），按用户所选生成模式（原生/节省）、分辨率、比例、时长、声音请求，不用原生价代替节省模式价。报价缓存 30 秒。报价缺失、单位或档位异常时停止新请求，不静默降级。
- 预估接口未正确采用参考视频信息，所以含参考视频时取它的生成与增强基线，再按 token 公式补齐参考成本：token = ((输出秒数 + max(输入视频秒数, ⌈输出秒数 × 2/3⌉)) × 24 + 1) × 像素数 / 1024。参考音频不算视频秒数。预估成本向上取到 0.001 元。
- 结算优先用上游 `billing.status=confirmed` 的 `charged_cny`（人民币，不再乘折扣，不和预扣重复相加）。节省模式是低清生成再增强，账单含生成费和增强费：增强任务没有明确人民币账单时，单独的 token 不足以证明全额成本，不能漏掉增强费直接退款。
- 任务里的 `estimated_cost` / `actual_cost` 单位未经供应商确认，只存留档，不当人民币。
- 新穗禾编辑请求冻结探测原片的精确秒数及 `suiheContract`：外层提交提示四舍五入、询价整数提示向上取整，参考视频提示保留小数；真实结算仍看原快照与上游确认账单。旧快照不补写新契约、不改历史报价；未确认契约/计价的穗禾延长暂不接新单。
- 新任务按冻结范围全自动准备全能参考、首帧/首尾帧、编辑附加图片，原图多槽/跨模式复用；旧快照不追加新的入库范围。
- 白名单/云库入库采购独立记录 `charged_credits`，不混作视频人民币实扣或再次乘折扣；答复中某 Key 当时零价不能当作永久承诺。Processing 可已扣采购，Failed 或断线未保证退款；保留 token/未知采购标志供核对，不自动反复上传。

2026-10-26 上游预估示例（5 秒、16:9、无参考素材、有声，采购成本，不含加价；`—` 为未开放组合）：

| 模型 | 分辨率 | 原生（元） | 节省（元） |
| --- | --- | ---: | ---: |
| 2.5 | 480p / 720p / 1080p | 2.746 / 6.175 / 15.282 | — / 3.173 / 3.473 |
| 2.0 | 480p / 720p / 1080p / 4K | 1.887 / 4.058 / 10.122 / 20.641 | — / 2.316 / 2.566 / — |
| 2.0 Fast | 480p / 720p | 1.124 / 2.418 | — / 1.559 |
| 2.0 Mini | 480p / 720p | 0.699 / 1.503 | — / 1.106 |

这些是该条件下的样本，参数不同必须重新询价，不能当成统一秒价。

### 火山方舟（Seedance 2.5、2.0 Fast，管理端切换时）

- 成本按官方 token 价（同上表 2.5、Fast 两行，无折扣），成功后以查询返回的 `usage.completion_tokens` 结算；该值已含官方最低用量，不再夹取第二次下限。
- 创建前按像素、24 FPS、输入与输出秒数和一帧尾帧余量预估：Fast 含输入视频时用官方 480p 最低 token 表按像素等比推算；2.5 含输入视频时下限为 (输出秒数 + ⌈输出秒数 × 2/3⌉) × 像素数 × 24 / 1024。比例为自动时取该分辨率的最大像素。预估不等于账单。
- 2.5 的 480p 16:9 按 854×480 计算。视频编辑报价用已探测的输入时长；多视频编辑按最长一条预估输出时长，全部参考视频计输入成本，成功按实际输出时长结算。

### 秘塔（MiniMax H3、Seedance 2.0 / Mini）

- 成本 = 秘塔积分 × 每积分人民币成本。每积分成本默认 0.0108 元（最小充值包，最贵档），管理端 `metasoRmbPerCredit` 可调（下限 0.008798，即 4399 元 / 50 万积分）。

  | 模型 | 档位 | 秘塔积分/秒（无参考视频 / 有参考视频） |
  | --- | --- | --- |
  | H3 | 480p / 768P / 1080p / 2K | 6.82 / 10.2 / 15.91 / 17（有无参考视频同价） |
  | H3 超过 15 秒 | 480p / 768P / 1080p | 13.64 / 20.4 / 31.82 |
  | Seedance 2.0 Mini | 480p / 720p | 16.20 / 9.82；35.09 / 21.23 |
  | Seedance 2.0 | 480p / 720p / 1080p / 4K | 50.61 / 30.67；108.89 / 65.83；271.77 / 165.40；553.67 / 340.73 |

- 带参考视频时按该档单价 ×（输出秒数 + 参考视频秒数）。H3 图片前 5 张免费，之后每张 5.7 积分；Context IR 每次 5.7 积分（节点打开「原样使用提示词」时不收）；音频免费，`usage.input_seconds` 可能含音频，要扣除，不能双算。Seedance 的图片和音频不另收费；比例和声音没有独立价档。
- H3 超过 15 秒（按请求时长判断）时，输出、参考视频秒数和超额图片整体按 2 倍计，Context IR 不翻倍。2K 最长 15 秒。
- 成本优先用上游返回的 `usage`（`output_seconds`、`input_seconds`、`input_image_count`），缺字段才用参数估算。
- Seedance 2.0 / Mini 的价格秘塔没有公开页面，数字来自 studio 定价界面；已由上游账单核对的只有 Mini 480p（16.20 积分/秒）。

### Grok 视频

- 采购成本 = 当前网关美元输出秒价 × 采购倍率 0.5 × 汇率（默认 7.2，管理端可调）：经典版 480p/720p $0.05/$0.07，1.5 版 480p/720p/1080p $0.08/$0.14/$0.25，1.5 Lite 当前网关回落到 1.5 价族，480p/720p/1080p 按 $0.08/$0.14/$0.25；官网 Lite 刊例 $0.02/$0.03/$0.14 不能替代当前渠道实际采购价。当前网关只按输出视频计费；新采购快照的输入图单价与输入视频秒价均为 0，不另收输入媒体费。xAI 官网的参考图刊例（经典版 $0.002/张、1.5 / Lite $0.01/张）与输入视频 $0.01/秒只作为审计说明，不冒充当前网关收费。旧快照保留原有单价，缺新字段的旧快照继续沿原估算，不重算旧任务。
- 新客户售价与实际采购分开：客户价 = 当前渠道美元秒价 × 管理端 `grokCustomerMultiplier`（默认 0.2，可设 0–100）× 汇率 + 每输出秒加价（默认 0.1）；实际采购仍用云枢倍率 0.5。分辨率人工价优先，调整全局售价倍率不会覆盖人工价。无人工价时的默认客户价（每输出秒）：经典版 480p/720p 为 0.172 / 0.2008 元，1.5 为 0.2152 / 0.3016 / 0.46 元，Lite 当前渠道同为 0.2152 / 0.3016 / 0.46 元。管理端利润按采购倍率 0.5 记录，不能将 0.2 冒充采购折扣。
- xAI 官方公告 Quality 于 2026-11-02 起重定向到 Image 2.0 low；当前仍保留独立入口，云枢订阅通道的切换与实际扣费需要单独核实。
- 新快照冻结采购倍率、售价倍率和人工价；旧快照没有 `customerMultiplier` 时沿原倍率或原人工价，不重算旧任务。倍率不等于订阅的实际现金分摊，渠道变化需重新核账。Grok 按受理时的预扣上限结算；有成片时长时允许按原快照退差，不追加超过预扣的扣费。
- 新版 Grok 延长任务按探测的原视频时长 + 用户选择的新增秒数预算最终成片；这属于输出预算，不是输入视频费。旧快照没有总长预算标志时保持原预算，提交上游的 `duration` 仍是新增秒数。

无人工价时 H3 的默认短视频基础价约为 480p/768P/1080p/2K 0.1737 / 0.2102 / 0.2718 / 0.2836 元每输出秒，另计 Context IR 0.06156 元/次和参考素材。

## 图片售价

| 模型 | 采购成本（元/张） | 默认客户价（积分/张） |
| --- | --- | --- |
| GPT Image 2 / 2.5 Sunburst / 2.5 Flare | 云枢账单 $0.201 | 0.10（固定） |
| Grok Imagine Image | $0.02 × 倍率 1 × 汇率（成本记录用） | 0.10（固定） |
| Grok Imagine Image 2.0 | low 1K/2K $0.04/$0.06；medium $0.06/$0.08，输入图 $0.01/张；× 倍率 1 × 汇率 | 0.10（固定） |
| Grok Imagine Image Quality | 1K/2K $0.05/$0.07，输入图 $0.01/张；× 倍率 1 × 汇率（售价低于成本） | 0.10（固定） |
| Seedream 5.0 Pro（方舟） | ≤261 万像素 0.30；>261 万像素 0.60；图层拆分 0.15 / 0.30 | 成本 + 0.10 |
| Seedream 5.0 Lite / 4.5 / 4.0（方舟） | 0.22 / 0.25 / 0.20 | 成本 + 0.10 |
| Seedream（穗禾，管理端切换时） | 4.0 1K/2K 0.40；4.5 2K 0.45；5.0 Lite 2K/3K 0.42；5.0 Pro 1K/1.5K/2K 0.60/0.85/1.20 | 成本 + 0.005 |

- 5.0 Pro 的参考图首张免费，第 2 张起每张 0.02 元按官方原价另加，不加价；后台手动定价时不另加。
- 判断 5.0 Pro 价档要看实际像素（智能 `2K` 按高档）：穗禾档名与官方像素档不一一对应，比较要用相同实际尺寸、参考图数量和场景。
- 火山图层拆分的新任务在接纳时冻结 `imageLayerPricing`（版本 `ark-image-layers-v1`）：采购小/大档、客户小/大档、261 万像素分界和按次输入图费。管理员人工价优先；已接纳后调价不重算快照。按最多 17 张与冻结客户最高档预扣，再用每张原始 PNG/JPEG 的真实像素档结算，实扣不超过预扣额。旧任务没有该字段时沿用原按张数计价，不补快照、不改历史。
- 新图层任务如无法可靠解析原始输出尺寸，先保存全部原件；保存成功后将 `imageLayerSettlement.status` 记为 `unconfirmed`、该单客户实扣为 0、预扣全退且以后不补扣。采购成本保留 `rmb:null`，清除这笔任务的旧估价回落；管理端显示成本和差额未知，不把它记成供应商免费。保存失败继续沿原任务保存/取回，不重新生成。此保护只用于新图层快照，不改变正常售价或旧任务。
- 服务端代码回退前应停止接纳新图层请求，并保留能处理已有 `ark-image-layers-v1` 任务的结算入口直至这些任务完成；不通过删除快照或覆盖数据库回滚价格。
- 积分保留两位小数（穗禾渠道四位），最低 0.01。
- 后台覆盖：`settings.prices[模型ID].image` 可设统一单价，或按尺寸设单价并用 `default` 保留其余尺寸。统一数字改为尺寸表时旧数字自动成为 `default`；只改一个尺寸不重置其他尺寸；显式空表 `{}` 清除覆盖。模型目录、管理端价目和新请求报价使用同一有效价格。

## 文本

- Agent 文本计费由管理端开关（`agentEnabled`）控制，默认关闭；各文本模型按 token 的价格默认为 0；可按用户设置继承、免费或付费及倍率。模型返回的 token 统计照常保留用于展示和排查。
- 短文本接口和媒体生成沿用各自账本，不能把 Agent 不计费推广为所有请求免费。文本调用不计入媒体成本统计。

## 成本记录与对账

- 每次生成留存请求、上游任务 ID、响应、用量、成本金额与完整计算依据（`upstream_calls` 与 `generations.upstream_cost`，密钥不进留档）。成功结算、用户实扣/退款和成本记录在同一事务提交；后到的日志不得把终态成本降级为预估。
- 成本依据明确区分：上游账单（如穗禾 `charged_cny`）、上游用量推算、参数预估、价目参考推算、成本未知。只有真实逐单账单才能称为供应商实扣；共享账号的余额差和历史均值不能归属到某一单，也不能证明净利。未知成本留空，不当 0。
- 当前没有自动读取供应商逐单账单，管理员凭原请求 ID 查账。失败、拒绝、取消和结果不明的上游费用不默认当作 0。
- 管理端 `GET /api/admin/upstream-calls`（逐条明细）和 `GET /api/admin/derived-prices`（按上游 × 模型 × 档位汇总真实用量）用于对账。秘塔快照优先比较累计消耗增量，缺失时才用余额变化，结论是窗口诊断，不是逐单核对。
- 管理总览分别展示账本净消耗（含已删除生成索引但仍有账本的请求）和留存生成索引实扣；两者范围不同，差值不是漏扣。用户月消耗按本期预扣减去全部退款后的净值统计，排队/运行中的预扣另列，管理员调整不算生成消耗。缺少原请求成本时不按当前价格补算。
- 内部成本快照只给管理员读，普通用户响应必须剔除。管理端模型主表只显示状态与档位积分，自动计价模型显示“按参数报价”；成本参数折叠展示。

## 校验工具

`npm run verify:admin-pricing` 与 `node scripts/verify-video-pricing.ts` 用隔离 SQLite 和注入的上游响应检查参数组合、预扣/退款、历史快照、人工价、报价接口与单位，不发真实生成请求，不代替真实出片验收。
