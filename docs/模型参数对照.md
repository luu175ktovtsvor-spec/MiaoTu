# 模型能力与传参（内部）

只给服务端、管理端和开发者看。公开接口、画布和节点只出现模型 ID、能力和积分，不出现供应商、渠道、上游模型 ID 或成本。

## 总原则

- 每个模型的模式、比例、清晰度、时长、张数和参考素材上限只在服务端目录定义一次：`server/image-models.ts`，穗禾实时能力由 `server/suihe-catalog.ts` 叠加。画布节点只读目录里的 `sizes`、`ratios`、`durations`、`modes`、`parameterRules`、`controls`；Agent/MCP 读 `node:getConfig`（视频看 `modeGuide`）；服务端校验和询价用同一份目录。前端不按模型 ID 另写菜单。
- 上游支持的能力都要开放；暂不开放的在本文写明原因。上游不支持的不显示、服务端拒绝；不用别的模式冒充（如用全能参考冒充首尾帧）。
- 视频模式菜单按已连素材的类型和数量启用，不满足的模式置灰；旧画布的模式仍保留，素材不符合时提示并在发送前拦下。工具接口允许先配置模式再补素材。只有未明确选择或选的是文生视频时，才按连入的素材自动切换。
- 只开放有报价的档位；上游有、但没有采购价的组合不显示。
- 服务端对已安装旧客户端发来的不合规参数只做纠正（例如把文生视频的“自适应”改发 16:9、图片尺寸与比例不一致时以尺寸为准），不拒绝原本可用的请求。

### 管理端渠道开关

- 管理端模型目录一行一个客户端模型，显示模型 ID、当前上游、上游模型 ID、渠道配置与开关。开关保存在 `settings.modelChannels`，例如 `{"seedance-2.5": {"suihe": true, "ark": false}}`；`settings.models[模型ID]` 是客户端总开关。
- 管理端设置优先于源码默认值；某模型一旦有显式渠道表，没写到的渠道视为关闭。打开一个渠道即设为当前路由并关闭该模型的其他渠道；关闭当前渠道则该模型关闭，不自动改走其他上游。
- 新任务在预扣前再次按当前渠道解析，忽略客户端传来的上游标记；已受理的任务保留创建时的渠道快照（`provider` / `upstreamProvider`），后台切换不影响它们。尺寸、默认参数和报价随实际渠道切换。
- 源码默认值不代表线上已切换：部署前和排障时在管理端核对实际渠道。

## 视频：Seedance（穗禾）

接口：根地址 `https://api.suihemedia.cloud`（`SUIHE_BASE_URL` 只在服务端配置），`GET /v1/models` 读取 `request_model` 与实时能力，`POST /v1/videos/generations` 提交，`GET /v1/tasks/{task_id}` 轮询。只保存响应里的 `task_id`，`id` 不能替代。公开模型目录不等于当前 Key 的权限清单，也不含逐单报价。

| 模型 | 时长 | 清晰度（原生 / 节省模式） | 当前公开模式 | 参考上限 图/视频/音频 |
| --- | --- | --- | --- | --- |
| 2.5 | 4–30 秒 | 480p/720p/1080p / 720p/1080p | 文生、首帧、首尾帧、全能参考、编辑 | 30/10/10 |
| 2.0 | 4–15 秒 | 480p/720p/1080p/4K / 720p/1080p | 文生、首帧、首尾帧、全能参考 | 9/3/3 |
| 2.0 Fast、2.0 Mini | 4–15 秒 | 480p/720p / 720p | 文生、首帧、首尾帧、全能参考 | 9/3/3 |

- **传参**：文生、首帧、首尾帧统一发 `function_mode=first_last_frames`；新任务的普通图片先由服务端自动准备白名单，Active 后用字符串字段 `first_frame_url` / `end_frame_url`。全能参考发 `omni_reference`；2.5 编辑发 `video_edit` + 原片 `video_file_1`，附加图片同样自动准备，已登记的图片库引用放在 `materials`；旧快照或准备失败的兼容路径仍用 `image_file_N`，两者可混用但不重复发送同一图片。分辨率字段为 `video_resolution`。
- 生成模式（原生 `native` / 节省 `super_economy`）和功能模式是独立字段；480p 只有原生，4K 只有 2.0 原生，最终选项取实时能力与各模式清晰度规则的交集。
- **比例**：2.0/Fast/Mini 固定 16:9、9:16、1:1、4:3、3:4；2.5 有实际首帧时与编辑使用 `adaptive`。纯文生不能发 `adaptive`。固定比例即使被接受后改为自适应，也不代表上游保证按指定比例裁切。
- **素材**：图片 ≤30MiB、视频 ≤200MiB、音频 ≤15MiB（等于上限可接受），本机视频/音频必须读到有限正时长。2.0/Fast/Mini 全能参考不能仅音频；参考视频单条 2–15 秒、合计 ≤15 秒，2.5 为单条 2–30 秒、合计 ≤30 秒。2.5 编辑原片 4–30 秒，保持原片时长与比例。新请求以探测时长四舍五入的正整数作外层 `duration` 提示，精确秒数作 `reference_video_duration`；询价整数提示向上取整，不能把这些提示当成实际计费时长。
- **延长边界**：当前适配使用的 `omni_reference + extend + adaptive` 已由供应商确证返回 400；改为固定比例只通过首层检查，完整生成契约、时长含义、素材组合和报价仍未确认。因此暂不公开新的穗禾延长请求，底层适配保留供后续接入，旧已受理任务的查询/取回不受影响。火山原生延长独立保留；不能据此宣称上游永不支持延长。
- 新穗禾视频请求冻结私有 `suiheContract` 版本及编辑原片精确秒数，排队重放保留既有 `suiheCost` 报价快照；旧任务无新契约标志时保留原提示/询价规则。客户端不能自选旧契约或报价。
- 任务以 `status` 判成败；HTTP 200 可携带 `status=failed`。人像拒绝文字只用于安全提示分类，不作为鉴权或唯一业务码。错误诊断优先读顶层 `code`，再读 `error_detail.code`。

### 人物白名单

由服务端准备和复用白名单，不新增人物识别或人物库界面。供应商可能先受理任务再以“参考图可能含人像”拒绝；生成账单与入库采购分别核对，不能承诺失败入库自动退款。

- 新穗禾视频任务全自动准备已开放模式的所有图片槽：全能参考的 `image/images`、单首帧与首尾帧的 `firstFrame/lastFrame`、编辑视频的附加图片。使用原始图片字节，不判断是不是人物，不修改真实原图，不新增人物库界面；视频与音频保持原文件链路。供应商认为普通图不必入库，当前全自动策略会让普通图也占用配额，并可能产生入库采购费用。
- 新任务私有快照 `suiheContract.imageLibraryPreparation=all_image_slots` 冻结扩展范围；旧快照没有该字段时仍按原全能参考图片范围处理，旧首帧/编辑不补做新增入库，旧已受理任务不重新提交。
- 内容去重用用户、library 和完整 sha256；同进程同一用户同字节素材的多槽、跨模式的并发准备合并为一次上传。优先保存 `reference_id ?? id`，Processing 状态收到的 token 立即持久化。超时、未知状态或 Failed 已有 token 时，下次只查原记录，不自动重传采购；上传结果断线且无 token 时记录未知，须可信查询/人工核对后再决定，不能盲目重传。只有权威 404 证明素材已不存在时才允许重新准备。
- `Active` / `Processing` / `Failed` 大小写不敏感；未知状态继续等待。每 2 秒查询、默认 2 分钟等待是客户端策略，不是供应商处理时限保证。入库未就绪时拒绝本次生成；上传、下载异常或 Failed 的兼容回退保留普通引用，可能再次被模型拒绝，但不会据此自动重复购买入库。
- **本地归属是必需鉴权**：上游生成解析不核对 Sub-Key，详情 404 不能证明生成已隔离。预扣前与提交前，原始 `whitelist://` / `asset://` 引用必须在本站用户 owner registry 中登记，再按该用户 Sub-Key 查状态。无归属的外部 token 须经受信上传、查询或导入登记，不能任意直用。受信列表/详情返回的合法新别名可绑定当前用户；不以 token 相等判断素材相同，也不把一个用户的别名转给另一用户。
- 兼容增量表 `suihe_library_references` 保存用户/library/token 别名，并从旧 `suihe_library_assets` 迁入已知 owner；内容缓存仍用 sha256。任务查询上游只需主 Key，本站继续以原任务/user 映射校验归属，不因是否带 Sub-Key 改变查询授权。
- 可信白名单列表为带当前用户 Sub-Key 的 `POST /v1/asset-library/whitelist/list`，页大小最多 100，属于该命名空间自己的素材，不是公共预设人物目录。列表别名登记仅供受信后端调用；本轮未新增公开导入入口。
- `charged_credits` 按每次实际操作记录；供应商答复中当前 Key 的价格为 0 仅是当时事实，Processing 也可能已采购扣费，不能推广为所有 Key 永久免费或失败必退。配额以主 Key + Sub-Key 为范围，云库项也可能计入。云库仅接图片/音频，不接新视频上传。

## 视频：Seedance（火山方舟，管理端切换时）

适用于 Seedance 2.5（`doubao-seedance-2-5-260628`）和 2.0 Fast（`doubao-seedance-2-0-fast-260128`）。

- 提交 `POST https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks`，查询 `GET .../tasks/{id}`（只保留 7 天）。结果视频 URL 只有 24 小时有效，成片要立即取回。
- `content` 角色：图片 `first_frame` / `last_frame` / `reference_image`，视频 `reference_video`，音频 `reference_audio`。首帧、首尾帧、全模态参考三种场景互斥：首尾帧模式拒绝额外参考图，参考模式拒绝首尾帧字段。2.5 允许只放音频，2.0 系列需要至少一张图片或一段视频。火山参考类生成允许省略文本提示；文生、显式编辑与延长仍需要对应描述。尾帧必须与首帧一起传入。
- 2.5：4–30 秒，480p/720p/1080p，比例 21:9/16:9/4:3/1:1/3:4/9:16/adaptive，参考 30/10/10；首帧、首尾帧、编辑、延长只发 `adaptive`；编辑发 `duration=-1`、`ratio=adaptive`。1080p 原片是 10bit HEVC，不为浏览器预览改写原片。
- 2.0 Fast：4–15 秒，480p/720p（没有 1080p，带参考也不改发 1080p），参考 9/3/3，模式含文生、首帧、首尾帧、编辑、延长、全模态参考；编辑/延长通过 `reference_video` + 提示词判定，没有单独端点。
- 时长列表含 `-1`（界面显示“自动”），预扣按该型号最长秒数，成功后按实际用量结算。
- `generate_audio` 始终显式发送（用户关声音就发 false）；选填项：返回尾帧（`return_last_frame`）、联网搜索（`tools: web_search`，仅文生）。
- 2.0 系列不接受 `seed`、`camera_fixed`、`frames`，服务端在预扣前拒绝；样片 `draft` 和离线推理 `flex` 2.0 系列不支持，未开放。
- 成本依据是查询返回的 `usage.completion_tokens`（已含最低用量）。

## 视频：秘塔

提交 `POST https://metaso.cn/api/minimax/v2/video_generation`，查询 `GET /api/minimax/v2/query/video_generation/{task_id}`（task_id 是路径段），视频在 `task.content.url`（带签名的 `files.metaso.cn` 链接）。状态 `success` 归一为内部 `succeeded`。这是任务插件协议；OpenAI 兼容的 `/v1/videos` 只支持单图 + 提示词，不用。

请求体 `{ model, content, duration, resolution, ratio, context_ir_enabled }`，`content` 为 `text`、`image_url`（`first_frame` / `last_frame` / `reference_image`）、`video_url`（`reference_video`）、`audio_url`（`reference_audio`）。普通单图和混合参考用 `reference_image`，只有首尾帧模式用 `first_frame` / `last_frame`。

**MiniMax H3**（默认渠道）：

- 480p/768P/1080p 为 4–30 秒，2K 为 4–15 秒；超过 15 秒按官方长视频档计价。
- 模式：文生、首帧可选/首尾帧、多图/视频/音频混合参考（9/3/3）。首尾帧可以和参考**图片**同时使用（只有 H3 支持），带参考视频或音频时不能同时用首尾帧。
- 比例：首尾帧模式可选全部 7 档（adaptive、21:9、16:9、4:3、1:1、3:4、9:16）；文生和混合参考不提供 adaptive。
- 参考视频单条 2–15.5 秒、画面 256–5760 像素，时长由服务端 ffprobe 读取原文件。
- 声音由模型原生输出，协议没有声音开关，界面不提供假开关。
- `context_ir_enabled`（提示词优化，秘塔默认开启并按次计费）每次显式发送：默认 `true`；节点「原样使用提示词」打开时发 `false`，预扣和结算都不含这一项。
- 查询返回 `usage`（`output_seconds`、`input_seconds`、`input_image_count` 等），成本优先按它计算。
- **未开放**：`callback_url`、`aigc_watermark`、`fast_mode`（优先通道，价格 2 倍）、视频再生成（768P → 2K，需白名单）；`512p` 目录里有但没有价目，不显示。

**Seedance 2.0 / 2.0 Mini**（管理端切到秘塔时）：

- 模型字段 `seedance-2.0` / `seedance-2.0-mini`；必须发 `context_ir_enabled:false`。
- 4–15 秒（没有自动时长）；2.0 为 480p/720p/1080p/4K（发送前把 `4K` 归一为秘塔枚举 `4k`），Mini 为 480p/720p。
- 比例：文生和混合参考为 21:9/16:9/4:3/1:1/3:4/9:16；首尾帧固定 `adaptive`。首尾帧不能和参考图混用。
- 参考上限 9/3/3，视频、音频各自合计 ≤15 秒，不能只放音频；声音由模型原生输出。

成片由服务端同源代理 `/api/imagine/video-content?requestId=...` 取流（透传 Range），画布只拿到本账号的代理地址。

## 视频：Grok（云枢 Grok）

提交 `POST {YUNSHU_BASE_URL 去掉结尾 /v1}/v1/videos/generations`，响应的 `request_id` 是任务 ID，查询 `GET /v1/videos/{request_id}`，终态 `done`，视频在 `video.url`。字段按 xAI 命名：

- 文生：`{ model, prompt, duration, aspect_ratio, resolution }`；单图首帧加 `image: { url }`；参考图用 `reference_images: [{ url }]`。
- 三个模型都支持 1:1/16:9/9:16/4:3/3:4/3:2/2:3/21:9/5:2，1–15 秒；`generate_audio` 显式发送，关声音时发 false。
- 图生视频（单图）官方忽略 `aspect_ratio`，输出跟随图片：画布显示「跟随素材」，服务端不发比例；旧客户端发来的比例直接忽略，不拒绝。
- 1.5 Lite `grok-imagine-video-1.5-lite`：只有文生和图生，1080p 由 720p 放大，不支持参考图、预设声音、首尾帧和关键帧。云枢 Grok 账号的模型映射里要有这个 ID 才能调用。

| | 经典版 `grok-imagine-video` | 1.5 `grok-imagine-video-1.5` |
| --- | --- | --- |
| 清晰度 | 480p/720p | 480p/720p/1080p（参考图、带尾帧或关键帧时最高 720p；首尾帧模式只给首帧且不带声音参考可到 1080p） |
| 模式 | 文生、单图、参考图（最多 7 张，最长 10 秒）、编辑、延长 | 文生、单图、参考图（最多 14 张）、首尾帧（`image` + `last_frame`） |
| 限制 | 拒绝 `last_frame`、`keyframes`；单图钉帧和参考图不能同一请求，做成两个互斥模式 | 不支持编辑与延长 |

- 编辑/延长只有经典版：分别调用 `/v1/videos/edits`、`/v1/videos/extensions`，只传 `video: { url }` 和提示词（延长另传 2–10 秒 `duration`）。编辑输入最长 8.7 秒，比例/分辨率/时长跟随输入；延长输入 2–15 秒，所选 `duration` 是新增 2–10 秒，上游按最终成片时长计费。新请求按「原片真实时长 + 新增时长」预算最终输出，按成片实际时长沿原快照结算且不超过预扣；旧快照没有总长预算标志时保留原规则，不另造输入媒体费。两者输出最高 720p，画布禁用无效控件。
- 1.5 的参考模式可在设置中独立选择首帧与尾帧（均可省略，可选同图做循环），并为连入图片指定最多 4 个关键帧时间；关键帧绑定原节点输出，重排引用不会换图。MCP `setConfig` 用 `pinnedFrames` 与 `keyframes` 配置，字段引用来自 `getConfig.keyframeImages`。询价和提交均按原图签发只读链接。
- 1.5 另支持关键帧 `keyframes: [{ image: { url }, timestamp_s }]`（最多 4 个，时间点在视频内部并对齐 1/3 秒，最高 720p）和预设声音 `reference_audios: [{ voice_id }]`（最多 3 个，画布在参考类模式的设置里选常用 eve/ara/leo/rex/sal，也可输入其他有效 voice_id，常用名单写在目录 `referenceVoices`；服务端只校验数量与格式，其余声音 ID 由 xAI 判定），支持仅选预设声音而不连图片；任何带预设声音的请求最高 720p。服务端按此校验。上传自有音频参考需要 xAI 受信合作方权限，普通画布不把上传音频伪装成 `reference_audios`。

## 图片：Seedream（火山方舟官方）

接口 `POST https://ark.cn-beijing.volces.com/api/v3/images/generations`，字段覆盖 `prompt`、`image`、`size`、`output_format`、`response_format`、`watermark`、`background`、`sequential_image_generation(_options)`。

每个清晰度档位都开放 1:1、4:3、3:4、16:9、9:16、3:2、2:3、21:9 八个比例的官方像素值，另保留只传档位、由模型定比例的「智能」档。高级设置可输入自定义宽高，服务端按像素范围与 1/16–16 宽高比校验。默认尺寸为目录第一项。

| 模型 | 档位 | 像素范围 | 格式 | 参考图 | 张数 |
| --- | --- | --- | --- | --- | --- |
| 5.0 Pro | 1K / 1.5K / 2K | 921600–4624220 | png/jpeg | 10 | 1 |
| 5.0 Lite | 2K / 3K / 4K | 3686400–16777216 | jpeg/png | 14 | 组图最多 15，参考+生成 ≤15 |
| 4.5 | 2K / 4K | 3686400–16777216 | jpeg | 14 | 组图最多 15，参考+生成 ≤15 |
| 4.0 | 1K / 2K / 4K | 921600–16777216 | jpeg | 14 | 组图最多 15，参考+生成 ≤15 |

5.0 Pro 专有：

- 透明背景 `background=transparent`：仅图生图、单张带透明通道的 png 输入、输出 png，服务端请求前校验。
- 图层拆分 `layer_decomposition`：单张 png/jpeg 参考图，262144–36000000 像素，尺寸 1K/1.5K/2K/auto；最多返回 1 张底图 + 16 个透明图层。新请求冻结大小两档采购/客户价，按 17 张最高档预扣，按每张原始成品实际像素档结算，人工价优先，实扣不超过预扣。旧任务无新快照时沿用原计价。底图留在原生成节点，其余图层各建一个独立图片节点。
- 提示词优化 `optimize_prompt_options`：标准 / 极速。
- 局部编辑：标注式（GPT Image 为蒙版式）。
- 未开放：`stream`；Pro/Flash 不提供 Lite 专属 `tools`。

5.0 Lite 支持 `web_search`，节点控件传入 `tools:[{type:"web_search"}]`，返回的 `usage.tool_usage.web_search` 保留查询依据。图片场景专属搜索采购费尚需供应商账单确认，不能套用其他服务的搜索单价或追加未报价的客户扣费。

## 图片：Seedream（穗禾，管理端切换时）

接口 `POST /v1/images/generations`，参考图优先 multipart 原文件，结果同样按 `task_id` 轮询。只开放有采购价的档位：4.0 为 1K/2K，4.5 为 2K（两者的 4K 没有采购价，不开放），5.0 Lite 为 2K/3K，5.0 Pro 为 1K/1.5K/2K。比例为上述八档；一次 1 张；不支持自定义尺寸、透明背景、图层拆分。格式只有 5.0 Lite 可选 jpeg/png，其余实际只返回 JPEG，只显示 jpeg。

## 图片：GPT Image（云枢）

OpenAI 兼容图片接口 `POST {YUNSHU_BASE_URL}/images/generations`。

- 尺寸：`auto`、`1024x1024`、`1536x1024`、`1024x1536`、`2048x2048`、`2048x1152`、`2160x3840`、`3840x2160`，另可自定义宽高（16 的倍数、比例 1:3–3:1、边长 ≤3840、655360–8294400 像素）。
- 质量：`auto` / `low` / `medium` / `high`，2.5 另有 `xhigh` / `max`；界面选择自动时显式透传 `auto`，旧客户端省略质量仍按原有 medium 默认。格式 png/jpeg/webp；参考图最多 16 张；一次最多 10 张；支持透明背景和蒙版局部编辑。GPT Image 2 不发送旧客户端保存的 `input_fidelity`。

## 图片：Grok（云枢 Grok）

- 不接受像素 `size`：比例 `aspect_ratio` 和清晰度 `resolution` 是两个独立字段。比例 16 档：auto、1:1、16:9、9:16、4:3、3:4、3:2、2:3、2:1、1:2、19.5:9、9:19.5、20:9、9:20、21:9、5:2；清晰度 1k/2k，全部组合可选。
- 质量 `auto` / `low` / `medium` 只属于 `grok-imagine-image-2.0`，省略时为 `auto`。`grok-imagine-image-quality` 是高画质版本，参数同经典版。一次 1–10 张。输出格式由清晰度决定，不提供格式开关。
- xAI 已公告 Quality 于 2026-11-02 起重定向到 Image 2.0 low；保留 ID 与用户已确认售价，网关订阅通道的实际行为需另行核实。
- 参考图最多 5 张：零张走生成接口，一张用 `image`，多张用 `images` 数组按输入顺序发送全部原图，不重复发送 `image`。

### 暂不开放及原因（GPT Image / Grok）

| 选项 | 当前边界与原因 |
| --- | --- |
| GPT Image `output_compression`（0–100） | OpenAI 与当前网关可传 JPEG/WebP 压缩级别；节点目录、设置面板及 MCP 尚无入口。本轮未增加该参数，不能说成上游不支持。 |
| GPT Image `moderation`（auto/low） | OpenAI 与当前网关可传；节点尚未提供选择入口，沿用上游默认 `auto`。 |
| GPT Image `background=auto` | 服务端可接受，上游可自动选择；当前节点与 MCP 只提供保留背景／透明背景两项，尚未提供自动背景选择。 |
| GPT Image `stream` / `partial_images` | 网关支持流式与部分图像参数；妙图当前图片链路只解析完整 JSON 回执并保存最终图片，尚未实现图片 SSE／部分图像消费，不向节点公布这些开关。 |
| GPT Image 2.5 `markup` | OpenAI 支持带透明标注的 PNG 编辑输入；当前网关请求解析与转发没有该字段，需先补网关，不能只增加客户端选项。已有蒙版 `mask` 编辑与此不同。 |
| GPT Image `file_id` 输入 | OpenAI 可使用文件 ID；当前网关明确拒绝 `images[].file_id`，接受图片 URL 与上传文件。妙图以本机原始素材调用，不提供文件 ID 入口。 |
| GPT Image 蒙版局部重绘的多张输出 | 普通生成和参考图编辑已支持最多 10 张；现有局部重绘工作流仍只提交、保存 1 张，节点隐藏多张选项。此为当前产品工作流边界，并非模型最多只能编辑 1 张。 |
| Grok 图片 `1.5k` 清晰度 | 官网价目出现该档，但生成能力文档只列 `1k` / `2k`，当前网关规范化也只识别这两档。尚未把价格条目当成可用参数开放。 |
| Grok 图片 `deferred` | 官方有异步图片请求；当前图片链路只接受同步最终图片回执，未实现该任务 ID 的查询恢复。视频异步任务链路不能代替图片 deferred 协议。 |
| Grok 1.5 自有音频文件作为声音参考 | 官方仅对受信合作方开放，当前订阅账号没有这项资格的证据；节点提供预设 `voice_id`，不把上传音频伪装成已获资格的输入。 |


## 参考素材怎么交给上游

1. 桌面本机运行时读取工作区素材（`/api/imagine/reference-url` 是桌面本机路由），上传到服务端 `desktop/references`。
2. 服务端校验文件属于当前用户，签发 6 小时有效的只读链接 `https://miaoimg.cn/api/imagine/reference?t=<token>`（token 绑定用户 + 路径 + 修订号 + 过期时间，HMAC 签名）。
3. 秘塔 / 火山按链接抓取（支持 Range）；穗禾走 multipart 原文件。
4. 视频、音频的真实时长由服务端 ffprobe 读取原文件，元信息按修订号缓存、并发上限 2；读不到时长在扣积分前拒绝。客户端上报值不作为计费依据。

`server/reference-input-contract.ts` 保存按渠道核实的输入格式、字节、时长和尺寸范围，询价和下单共用。供应商文档或能力接口变化时重新核实；未经核实的守卫值（如云枢/Grok 的 30MB）不说成模型官方上限。

## 文本模型

- 渠道：云枢（`YUNSHU_API_KEY`）、云枢 Grok（`GROK_API_KEY`）、DeepSeek（`DEEPSEEK_API_KEY`），定义在 `server/text-model-registry.ts`。云枢文本走 OpenAI Responses 兼容接口（旧客户端保留 Chat 兼容入口）。
- 三条通道都按无状态方式调用：每轮携带完整已转换的上下文（含工具调用与结果），不依赖 `previous_response_id`。
- 未单独配置的文本模型使用妙图默认上下文预算 1,000,000 token，这是应用预算，不代表上游容量已实测；输出上限兜底 32768。GPT-6.1 Sol 按官方模型卡记为 1,050,000 上下文、128,000 最大输出，但网关的 Codex OAuth 路径会删除 `max_output_tokens`，客户端发送该值不等于上游执行了同样的上限。
