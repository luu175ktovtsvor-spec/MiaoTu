# 服务器排查与真实数据验收流程

## 分工和发布边界

最新完整源码保存在本地 `miaoimg` 和 `miaoimg-desktop` 项目中；服务器仅在发布期间使用临时构建目录，发布完成、提交同步本地后清理。不要保留多份旧源码，也不要删除其他正在工作的发布目录。生产机才有真实的容器、真实账号、真实积分、真实生成记录、真实媒体权限和真实 Nginx 路径；因此，凡是“现在到底是什么状态”“用户能不能看到”“这张图能不能读”，一律 SSH 到 `root@96.9.225.212` 看，不能用本地数据库或本地 Vite 的现象代替。

发布的固定顺序是：从一次干净提交打快照，把源码同步到服务器独立构建目录，在服务器原生构建镜像，先做模块和健康自检，再替换生产容器。发布只换容器，生产数据、媒体和密钥仍由 `/opt/miaoimg/` 下的 bind mount 提供。本文的两个脚本不提交、不部署，也不会替代发布脚本。

## 服务器目录收尾（2026-10-14）

- `/opt/miaoimg/`：线上持久数据、素材、下载文件与凭据；旧源码和旧 Git 已移除。
- `/opt/miaoimg-ops/`：必要维护文件，保持 `deploy/`、`scripts/`、`data/` 相对布局。现有文件为 `deploy/{sync_upstream_dataset.py,generate_previews.py,cleanup-production.py,snapshot-media.sh}`、`scripts/fetch_dataset.py`、`data/{dataset-manifest.json,public-corpus.json}`。同步服务调用 fetch 的普通下载入口，不使用其独立 `--prune` 入口。
- `miaoimg-sync.service`、`miaoimg-storage.service`、`miaoimg-media-snapshot.service`：入口已切换到 `/opt/miaoimg-ops/deploy/`，定时器启用状态保持原样。
- `/opt/miaoimg-source` 和 `site-more-media-20261014` 工作树：本次因另一会话正在更新官网素材而暂留；任务结束后核对本地已保存最新提交，再移除工作树和源码仓库。不要提前删除共享 Git。

运行容器直接使用镜像内代码，宿主机完整源码不是运行依赖。清理前仍须重新核对容器挂载、定时任务、运行进程工作目录及正在进行的构建；不能仅凭目录名字删除。数据库恢复备份保留，不按“旧源码”处理。

## 一条命令看生产真实状态

```bash
deploy/inspect.sh
```

脚本本地启动，内部执行 SSH；默认目标是 `root@96.9.225.212`、容器 `miaoimg`。临时查看其他机器可以这样写：

```bash
REMOTE_HOST=root@另一台机器 REMOTE_CONTAINER=miaoimg deploy/inspect.sh
```

机器读取用 JSON：

```bash
deploy/inspect.sh --json
```

脚本只调用 `docker inspect`、`docker image inspect`、`docker logs`、`curl`、`systemctl show`、只读文件统计和 SQLite `mode=ro` 查询。它不启动、停止、删除或重启容器和服务，不跑迁移，不执行 `UPDATE`、`INSERT`，也不写服务器文件。HTTP 结果中 `未知` 或 JSON 的 `null` 表示该路径/文件/权限在本次检查中不可读，不能被解释为“正常”。

报告各区含义如下：

- **这一版是什么**：镜像 tag、镜像创建时间、容器创建/启动时间、运行状态、Docker HEALTHCHECK、所有 `OIP_*` 和模型开关。变量名可以看，密码、token、secret、key、private 等值统一显示 `[REDACTED_SECRET]`。
- **服务是否真的活着**：从服务器宿主机回环地址探测首页、`/manage`，以及 web 代理后的 `/api/catalog`、`/api/prompts`、`/api/admin/session`；同时直接探测图片 API、档案 API 和管理 API 的内层端口。`401`、`404`、`405` 是真实 HTTP 响应，不会被伪装成“服务挂了”；`未知` 才表示没有拿到响应。管理 API 开了 `OIP_ADMIN_LOCAL_ONLY` 时，宿主机直探 4184 可能未知，但 web 代理路径仍是验收入口。
- **数据现状**：从生产 `management.sqlite` 读账号总数、启用/停用数、积分总额、订单状态、生成状态、`workspace_files` 行数和上游调用。当前 schema 若有 `upstream_calls.upstream_cost`，成本必须用 `json_extract(upstream_cost,'$.rmb')`；当前生产 schema 实际使用 `upstream_calls.cost_rmb`，脚本会标明成本来源，并另外报告 `generations.upstream_cost` 的 JSON 合计。
- **迁移状态**：分别报告 `projects` 表、`workspace_files.project_id`、`workspace_files.blob`、`media_layout` 表和布局值，然后给出老布局、新布局或半迁移结论。半迁移时不要猜下一步，更不要直接跑存量迁移。
- **媒体与磁盘**：统计 `media`、`images`、`previews` 的文件数和逻辑字节数，报告 `/opt/miaoimg` 磁盘余量、媒体快照目录的最新一份和总份数、快照状态文件、快照定时器下一次触发时间。
- **数据集同步**：报告同步 timer 的上次/下次触发、`sync-status.json` 的成功/失败与原因，以及容器实际读取的 prompts DB 行数。容器里的 archive API 可能使用镜像内 `/app/.oip/runtime` 或显式 `OIP_DB_PATH`，所以脚本优先在容器内只读核对，而不是只看宿主机同名文件。
- **最近异常**：读取容器最近 24 小时日志，按完整报错行去重并计数，最多列 20 条；日志里的疑似凭据会脱敏。
- **余额不变量**：逐个账号比较 `users.points` 和 `ledger.delta` 的累计值，列出不一致账号及差额。它检查的是账本是否能解释当前余额：余额正确但账本少一笔会让对账、退款、管理员查询和未来恢复失去依据；两边不等也不能靠“总额刚好相等”掩盖账号级错误。

## 用真实数据起验收容器

发布新镜像但还没有换生产容器时，先在服务器上执行：

```bash
deploy/acceptance-container.sh --image miaoimg:<新镜像 tag>
```

不传 `--image` 会使用服务器当前 `miaoimg` 容器的镜像，适合先验证脚本闭环。脚本会打印实际生成的容器名；也可以固定名字和备用端口：

```bash
ACC_WEB_PORT=5383 ACC_IMAGE_PORT=5385 ACC_API_PORT=5386 ACC_ADMIN_PORT=5384 \
deploy/acceptance-container.sh --image miaoimg:<新镜像 tag> --name miaoimg-acc-<时间戳>
```

服务器上的步骤是：

1. 在 `/opt/miaoimg/acceptance/miaoimg-acc-<时间戳>/data/` 创建临时目录。
2. 对 `/opt/miaoimg/.oip/runtime-data/management.sqlite` 执行 SQLite 在线 `.backup`，得到独立库副本。生产库文件本身不会成为容器挂载。
3. 对 `/opt/miaoimg/media` 执行硬链接复制。硬链接与生产文件共享 inode，所以媒体目录随后以 `readonly` bind mount 挂进容器；验收容器不能沿链接写生产字节。`images`、`previews`、`db` 也只读挂载。
4. 以 `ENABLE_MODEL_CALLS=false` 启动指定镜像，管理、图片、档案和 web 端口全部只绑定服务器 `127.0.0.1`。端口不会出现在公网。
5. 等首页、图片 API `/health`、档案 API `/health` 可读，检查媒体挂载的 `RW=false`，再发一个只读 `GET /api/catalog`。脚本会先记录生产端同一请求，再比较验收端响应；当前生产接口若省略 `videos` 字段，报告中的 `videos=0` 表示“接口没有返回该字段”，不替代 `inspect.sh` 对实际 SQLite `videos` 行数的核对。脚本同时打印生产库和副本的账号/生成/workspace 行数，供人工核对。

脚本成功后，在本地另开终端建立隧道：

```bash
ssh -N -L 4383:127.0.0.1:4383 root@96.9.225.212
```

然后用本地浏览器打开脚本输出的地址（默认 `http://127.0.0.1:4383/?studio=1`）。浏览器访问的是服务器上的验收容器，不是本地开发服务。

验收结束必须清理，使用脚本打印的实例名：

```bash
deploy/acceptance-container.sh --down miaoimg-acc-<时间戳>
```

`--down` 会删除该前缀的容器和临时目录，随后再次检查容器和目录均不存在。无参数的 `--down` 会清理服务器上所有 `miaoimg-acc-*` 验收实例；多人同时验收时使用具体实例名。生产 `miaoimg`、生产库和生产媒体不在清理范围内。

## 红线

> **只读边界**：`deploy/inspect.sh` 只看；不要给它增加启动服务、重启容器、删除文件、改 SQLite 的逻辑。需要写入、迁移、快照或同步时，必须使用对应的、明确授权的主机脚本，并在命令前说明影响范围。

> **存量迁移**：没有被明确告知时，不运行 `scripts/migrate-projects.ts --apply`、内容寻址迁移或任何存量数据修复。先 `inspect.sh` 看结构，必要时只做 `--report`，确认备份和回滚路径后再单独授权。

> **网络暴露**：验收容器的 `-p` 左侧必须是 `127.0.0.1`。不把备用端口绑定到 `0.0.0.0`，不为方便临时开放安全组；本地浏览器一律通过 `ssh -L` 隧道访问。

> **凭据**：不把 `OIP_ADMIN_PASSWORD`、任何 `*_KEY`、`*_TOKEN`、`*_SECRET` 或密钥文件打印到终端、报告、截图、JSON、Git 或镜像。脚本输出出现 `[REDACTED_SECRET]` 就保持原样。

> **主机脚本边界**：同步、媒体快照、预览生成和 timer 都是服务器主机职责，不属于镜像里的应用功能。改这些脚本要单独审查、单独安装、单独验证；不要把主机路径和凭据塞进 Dockerfile 或前端。

> **真实请求**：验收只读路径不发送生图、视频、支付或 OAuth 请求。真实上游调用会消耗额度，真实支付会产生外部副作用，必须另行授权。

## 常见问题 → 一条命令

| 现象 | 直接命令 | 先看什么 |
|---|---|---|
| 站点 502 | `deploy/inspect.sh` | 首页、`/manage`、三个 API `/health`、容器 HEALTHCHECK、最近异常；先确认是 web 还是内层 API |
| 图片读不到 | `ssh root@96.9.225.212 'docker inspect miaoimg --format "{{json .Mounts}}"'` | `/app/media` 是否来自 `/opt/miaoimg/media`、生产挂载是否可读，再看 inspect 的媒体权限和 HTTP 结果 |
| 同步失败 | `ssh root@96.9.225.212 'cat /opt/miaoimg/.oip/runtime-data/sync-status.json'` | `status`、`failureReason`、`updated_at`；再用 `systemctl status miaoimg-sync.timer --no-pager` 看定时器是否还在 |
| 想知道这一版是什么 | `deploy/inspect.sh` | 镜像 tag、镜像创建时间、容器启动时间，不以本地 Git 工作树代替 |
| 某人积分不对 | `deploy/inspect.sh --json` | `balance_invariant.mismatches` 的账号、余额、账本累计和差额；不要先手改余额 |
| 生成卡住不动 | `deploy/inspect.sh` | 生成状态是否一直 `queued/running`、容器日志是否有异常、图片 API `/health` 是否 200；不要用第二次生图请求“试一下” |
| 新镜像想看真实页面 | `deploy/acceptance-container.sh --image miaoimg:<tag>` | 副本计数、`GET /api/catalog`、`RW=false` 和 SSH 隧道地址 |
| 验收结束清理 | `deploy/acceptance-container.sh --down miaoimg-acc-<时间戳>` | 输出最后的“清理断言通过”，再确认生产 `miaoimg` 仍在运行 |

## 本流程的完成标准

排查完成的证据是服务器上的报告和具体 HTTP 结果；验收完成的证据是“数据库副本 + 只读媒体 + 备用端口 + 只读请求 + 清理断言”这一整条闭环。`bash -n` 只能排除脚本语法错误，不能替代真实服务器运行；本地构建、健康端点或历史输出也不能替代本次生产核对。


## 多浏览器与素材保存（2026-10-07）

画布保存携带本页读取的完整基线及修订号。服务端在同一事务内合并不同节点、不同字段的修改；同一字段冲突时保留本页内容并拒绝覆盖。前端可以先保存本页副本再同步。旧页面不能用文件列表中的新修订号覆盖旧画布。可见画布每 5 秒复核修订号，未变化返回 304；浏览器的视口位置独立保存。收到外部内容变更时重置结构撤销基线，避免撤销操作删掉其他浏览器的新节点。

生成记录固定账号、项目、节点目录。相同节点已有任务时返回原任务编号，在预扣前拦截重复生成。图片、视频结果由服务端写回原画布，查询失败继续查原任务。离开页面只脱离等待；明确的上游终态决定成功或失败。

历史卡片使用精简列表，不携带完整参考素材和上游响应；失败的视频仍按视频显示。原始视频从账号工作区播放，缩略图仅用于预览。普通用户提示说明可采取的操作，原始诊断保留在管理记录。AI 解释功能保留。

同一账号的相同内容共用一份 blob，画布、历史保留各自引用；不同账号独立存储。迁移不压缩原文件。执行 `scripts/migrate-media-blobs.ts --apply --verify-hashes` 前必须停止写入并设置 `OIP_MEDIA_MAINTENANCE=1`，备份数据库并保留兼容 blob 的回滚镜像。只回收已扫描、已校验的旧文件，不能递归删除素材目录。

以上为实现约定；具体上线版本和真实网页结果以本次验收记录为准。

内容寻址迁移后，后台按 blob 文件核对原件；索引目录可以是虚拟目录，不要求保留旧路径树。`_previews` 是可再生成的预览缓存，不属于孤儿原件。日常发布从明确的源码提交使用仓库 Dockerfile 原生构建，不连续以线上镜像为 FROM 叠加补丁层。构建通过后仍须可回滚部署及真实网页验收；空间保留范围、清理时机和历史归档恢复见 `deploy/README.md` 的“当前空间与清理规则”。
